Part 2: Which Point Is Closer?

Challenge (skip ahead if you can):

Got it? Skip to Part 3.

Given three points P, A, and B on a 2D plane, is P closer to A or to B?

Before coding: for P=(1,2), A=(0,0), B=(5,5):

  1. Compute the squared distance from P to A: $(1-0)^2 + (2-0)^2 = ?$
  2. Compute the squared distance from P to B: $(1-5)^2 + (2-5)^2 = ?$
  3. Which is smaller?
  • P to A: $1 + 4 = 5$
  • P to B: $16 + 9 = 25$
  • 5 < 25, so P is closer to A.

Notice: we didn’t need sqrt! Comparing squared distances gives the same answer (since sqrt never flips the order).

def closer_point(p, a, b):
    px, py = p
    ax, ay = a
    bx, by = b
    dist_a = (px - ax)**2 + (py - ay)**2
    dist_b = (px - bx)**2 + (py - by)**2
    if dist_a < dist_b:
        return "A"
    elif dist_b < dist_a:
        return "B"
    else:
        return "Equal"

On a number line, is 3 between 2 and 5?

Yes — $2 \le 3 \le 5$.

But what if the endpoints are given in reverse: is 3 between 5 and 2?

Still yes! The order of the endpoints shouldn’t matter.

Part 4: Do Two Segments Overlap?

Challenge (skip ahead if you can):

Write segments_overlap(s1, e1, s2, e2) that returns True if two 1D segments touch or overlap, False if they’re completely separate.

Got it? Skip to Part 5.

Two segments on a number line. When do they not overlap?

Only two ways to be completely separate:

  1. Segment 1 is entirely to the left of segment 2
  2. Segment 1 is entirely to the right of segment 2

Before coding: after sorting each segment into (lo, hi), when is seg1 entirely left of seg2?

When hi1 < lo2 — the rightmost point of seg1 is still left of the leftmost point of seg2.

Similarly, entirely right when hi2 < lo1.

Overlapping = neither of those is true!

    lo1, hi1 = min(s1, e1), max(s1, e1)

Quick Check: Why is it easier to check for separation and negate, rather than directly checking for overlap?

A. Separation is faster to compute

B. Overlap has many sub-cases (partial, containment, touching) but separation has only two

C. Python can only negate, not compare

Answer: B. Many ways to overlap (partial, full containment, touching). Only two ways to be separate (entirely left or entirely right). Checking separation and negating is simpler.

Part 6: Do Two Rectangles Intersect?

Challenge (skip ahead if you can):

Write rects_intersect(a, b) where each rectangle is (x1, y1, x2, y2). Return True if they overlap or touch.

Got it? Skip to the end.

Two rectangles (sides parallel to axes). When do they intersect?

Same trick as before — decompose into axes!

Project both rectangles onto the x-axis. You get two 1D segments. Do the same on the y-axis.

The rectangles intersect if and only if both projections overlap.

  • x-axis: do [x1_a, x2_a] and [x1_b, x2_b] overlap?
  • y-axis: do [y1_a, y2_a] and [y1_b, y2_b] overlap?

And “do two 1D segments overlap” is the function from Part 4!

Hint 1: project onto each axis — extract the x-ranges and y-ranges.

Hint 2: segments_overlap(x1a, x2a, x1b, x2b) and segments_overlap(y1a, y2a, y1b, y2b)

Look at how we got here:

  1. is_between(a, b, p) — 1D point between two others
  2. segments_overlap — 1D segment overlap (uses separation logic)
  3. point_in_rect — 2D = two calls to is_between
  4. rects_intersect — 2D = two calls to segments_overlap

The pattern: break a 2D problem into two 1D problems, solve each with a function you already wrote, then combine with and.

This is called axis decomposition, and it’s used everywhere in computer graphics, physics engines, and collision detection.
