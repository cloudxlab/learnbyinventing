Trying splits by hand got old fast, so now it's time to automate it. You're going to write a function that finds the best split for you. For every feature, it'll try the midpoints between neighboring sorted values as candidate cut points. Then it'll score each one by how much it reduces variance, and keep the winner. If there's a tie, keep the first. If there's nothing to split, return nothing. There's also an optional parameter for choosing which features to look at. It'll matter a lot in Part 4.
