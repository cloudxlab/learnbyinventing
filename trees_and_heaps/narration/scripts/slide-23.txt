# From Text to Tree: a Tiny Parser In Part 1 you evaluated expression trees that were built by hand. Real programs receive expressions as strings : . Turning the string into a tree is called parsing -- it's the front half of every compiler (your from Exercise 1.1 is the back half). Write for fully parenthesized expressions with the operators , , and non-negative integer numbers (no spaces): If the current character is a digit, read the whole number -- that's a leaf . If it is : parse the left sub-expression, read the operator, parse the right sub-expression, expect -- that's an operator . A recursive helper that takes the current position and returns works beautifully.

Up to now, you've been handed expression trees that were already built. But real programs receive expressions as plain text, so someone has to turn a string into a tree. That's called parsing, and it's the front half of every compiler. Your evaluator is the back half. Try writing it yourself, and think about how each open parenthesis tells you what to do next.
