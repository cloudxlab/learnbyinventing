The Catch — Balance

Insert 1, 2, 3, 4, 5, 6, 7 in that order. What shape do you get?

1
 \
  2
   \
    3
     \
      ...  → a chain, not a tree!

Every insert went right — find is back to O(n). Sorted input is the worst input for a plain BST.

Self-balancing trees (AVL, Red-Black) fix this by rotating nodes to keep the height at log n. Databases use B-Trees — the same idea, made disk-friendly.

Quick Check: You insert 1, 2, 3, 4, 5 (in order) into an empty BST. How many comparisons does finding 5 require?

A. 3 (balanced tree)    B. 5 (chain leaning right)    C. 1 (it’s the last inserted)    D. BST refuses sorted data

Answer: B. Each value is larger, so every insert goes right. The tree becomes a chain: finding 5 means walking all 5 nodes. This is why balanced trees matter.

A BST works, but it maintains total order and we only ever ask for the min. Can a structure that promises less be simpler? Enter the min-heap:

Heap rule: every parent ≤ its children. Nothing about left vs right!

The minimum is always at the root.

Because the heap is always filled top-down, left-to-right, we can store it in a plain list:

      /   \
     3     2        stored as: [1, 3, 2, 8, 5]
    / \
   8   5

def heap_push(heap, val):
    heap.append(val)
    i = len(heap) - 1
    while i > 0 and heap[i] < heap[parent(i)]:
        heap[i], heap[parent(i)] = heap[parent(i)], heap[i]
        i = parent(i)

def heap_pop(heap):
    if len(heap) == 1:
        return heap.pop()
    result = heap[0]
    heap[0] = heap.pop()
    i = 0
    while True:
        smallest = i
        l, r = left_child(i), right_child(i)
        if l < len(heap) and heap[l] < heap[smallest]:
            smallest = l
        if r < len(heap) and heap[r] < heap[smallest]:
            smallest = r
        if smallest == i:
            break
        heap[i], heap[smallest] = heap[smallest], heap[i]
        i = smallest
    return result

def heap_sort(lst):
    heap = []
    for x in lst:
        heap_push(heap, x)
    return [heap_pop(heap) for _ in range(len(heap))]

print(heap_sort([5, 2, 9, 1, 5, 6]))  # [1, 2, 5, 5, 6, 9]

Hint: push all, then pop all into a list.

Each of the 2n operations costs O(log n), so heap sort is O(n log n). Python ships this as the heapq module.

Quick Check: In a min-heap, which is guaranteed?

A. Left child < right child    B. Every parent ≤ both children; root is the min    C. Sorted left-to-right at every level    D. Smallest at bottom-left

Answer: B. The heap rule only says each parent ≤ its children. Siblings have no ordering guarantee. The root is the overall minimum (transitively).

Quick Check: When would you choose a heap over a BST?

A. Need to search for arbitrary elements    B. Repeatedly need the min/max, not arbitrary search    C. Need sorted iteration    D. Data has duplicates

Answer: B. A heap gives the min in O(1) and removes it in O(log n), but arbitrary search is O(n). A BST supports general search in O(log n). Pick a heap when all you need is “give me the most urgent item.”

def in_order_iter(node):
    stack = []
    current = node
    result = []
    while current or stack:
        while current:
            stack.append(current)
            current = current.left
        current = stack.pop()
        result.append(current.val)
        current = current.right
    return result

def parse(s):
    def _parse(i):
        if s[i].isdigit():
            j = i
            while j < len(s) and s[j].isdigit():
                j += 1
            return Node(int(s[i:j])), j
        i += 1  # skip '('
        left, i = _parse(i)
        op = s[i]; i += 1
        right, i = _parse(i)
        i += 1  # skip ')'
        return Node(op, left, right), i
    return _parse(0)[0]

The trade-off ladder: a dict promises the most (O(1) any-key) and pays in memory. A BST promises total order and pays log n. A heap promises only the min — and is the simplest of all.

Choosing a data structure = paying only for the promises you actually use.
