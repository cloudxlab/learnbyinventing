# How a dict works inside: Hash the key to a bucket index one arithmetic step Go directly to that bucket Collisions: each bucket keeps a short list to check That s why takes the same time whether the dict holds ten keys or ten million. This is called O(1) constant time.
# [Fragment 0]: Same idea at scale: a website splits a billion users across servers. Which server holds user 12345? . That s sharding .
# ---
Same idea works at planet scale. A website with a billion users can't keep them all on one machine, so it uses the user's ID to pick which server holds them. That's called sharding, and it's really just hashing again, with servers instead of buckets.
