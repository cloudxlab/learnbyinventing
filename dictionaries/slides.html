Part 1: Dictionary Basics

Challenge (skip ahead if you can):

Write count_items(items) that takes a list and returns a dictionary mapping each item to how many times it appears.

count_items(["a", "b", "a", "c", "b", "a"])  # {"a": 3, "b": 2, "c": 1}

Already got it? Skip to Part 2.

A dictionary maps keys to values — like an index at the back of a book.

d = {"apple": 3, "banana": 1, "cherry": 5}
d["apple"]    # 3
d["banana"]   # 1

You can add or update entries with d[key] = value:

d["date"] = 7       # adds a new entry
d["apple"] = 10     # updates apple from 3 to 10

What happens if you look up a key that doesn’t exist?

d["mango"] raises a KeyError. Use d.get("mango", 0) to get a default value instead.

Quick Check: You used a dictionary to count words. Could you have used a list of [word, count] pairs instead? What would be the main drawback?

A. Lists can’t store pairs

B. It would work identically with no drawback

C. Finding whether a word already exists would require scanning the entire list each time — much slower for large texts

D. Lists can’t be sorted

Answer: C. With a list you’d scan every pair to check if a word exists — that gets slow as the text grows. A dictionary jumps straight to the right entry.

Part 6: Inventing Hashing

d["banana"] is instant even if d holds a million keys. A list would check entries one by one. How does a dict jump straight to the right spot?

The answer: turn the key into a number, and use that number as a position.

def string_hash(s, n_buckets):
    total = 0
    for ch in s:
        total += ord(ch)
    return total % n_buckets

print(string_hash("a", 10))       # 7
print(string_hash("banana", 10))  # 4
print(string_hash("listen", 1000))  # 655

Try this:

string_hash("listen", 1000), string_hash("silent", 1000)

Both give 655. They’re anagrams — same letters, same sum. Two different keys landing in the same bucket is a collision.

def string_hash_v2(s, n_buckets):
    total = 0
    for i, ch in enumerate(s):
        total += ord(ch) * (i + 1)
    return total % n_buckets

print(string_hash_v2("listen", 1000))  # 292
print(string_hash_v2("silent", 1000))  # 299  (different!)

Hint: total += ord(ch) * (i + 1) using enumerate.

How a dict works inside:

  1. Hash the key to a bucket index — one arithmetic step
  2. Go directly to that bucket
  3. Collisions: each bucket keeps a short list to check

That’s why d[key] takes the same time whether the dict holds ten keys or ten million. This is called O(1) — constant time.

Same idea at scale: a website splits a billion users across servers. Which server holds user 12345? 12345 % n_servers. That’s sharding.

If you add an 8th server, % 7 becomes % 8 — almost every user is now on the wrong server. Real systems use smarter techniques (consistent hashing) to avoid reshuffling everyone.

Quick Check: Two different keys hash to the same bucket (a collision). What happens?

A. The second key silently replaces the first

B. Python raises an error

C. The bucket stores both pairs and lookup checks each one — still fast if collisions are rare

D. The hash function picks a different bucket

Answer: C. Each bucket keeps a short list of all key-value pairs that landed there. As long as the hash spreads keys evenly, the lists stay tiny and lookups remain fast.
