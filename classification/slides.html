You need to convert the following numbers into probabilities (fractions that add up to 1).

We get $(0.167,\; 0.833)$. The 5 is five times bigger than 1, but its share is only about five times bigger.

What if we wanted the biggest value to really dominate — to be pushed much closer to 1?

Part 2: Making Big Bigger

Challenge (skip ahead if you can):

Write a function that takes a list of numbers (possibly negative) and returns a list of probabilities (each between 0 and 1, summing to 1) where the largest value gets pushed much closer to 1.

Got it? Skip to Part 3.

We want to amplify differences before scaling.

Given $(1, 5)$, we want the 5 to end up with a share much larger than $\frac{5}{6} \approx 0.83$.

What mathematical operation makes big numbers much bigger while keeping small numbers relatively small?

Think of a few options. There is no single right answer — brainstorm!

  • Squaring? $1^2 = 1,\; 5^2 = 25$ → scale → $(0.038, 0.962)$
  • Cubing? $1^3 = 1,\; 5^3 = 125$ → scale → $(0.008, 0.992)$
  • Exponential? $e^1 \approx 2.72,\; e^5 \approx 148.4$ → scale → $(0.018, 0.982)$

All of these amplify! But there’s a problem with squaring and cubing — what happens if the input is negative?

If inputs can be negative (and they often are in ML):

  • $(-2)^2 = 4$ — a negative number becomes positive and big. That’s wrong — a small (negative) value should stay small.
  • But $e^{-2} \approx 0.135$ — small and positive. ✓

The exponential $e^x$ has a perfect property:

  • Large positive $x$ → very large output
  • Zero → output is 1
  • Negative $x$ → output is small but always positive

So our recipe is: apply $e^x$ to each value, then scale.

Part 3: Softmax

Challenge (skip ahead if you can):

Write softmax(values): apply $e^x$ to each element, then scale so the results sum to 1. Test it on [1, 5], [1, 2, 3], and [-1, 0, 1].

Got it? Skip to Part 4.

Let’s combine what we invented:

  1. Take each value $x_i$.
  2. Compute $e^{x_i}$.
  3. Divide each by the sum of all $e^{x_j}$.

In math:

$\text{softmax}(x_i) = \dfrac{e^{x_i}}{\sum_j e^{x_j}}$

Try it by hand on $(1, 2, 3)$:

  • $e^1 \approx 2.718, \quad e^2 \approx 7.389, \quad e^3 \approx 20.086$
  • Sum $\approx 30.193$
  • Softmax $\approx (0.090, 0.245, 0.665)$ — the 3 dominates!

import math

def softmax(values):
    exps = [math.exp(v) for v in values]
    total = sum(exps)
    return [e / total for e in exps]

print(softmax([1, 2, 3]))   # [0.090, 0.245, 0.665]
print(softmax([1, 5]))      # [0.018, 0.982]
print(softmax([-1, 0, 1]))  # [0.090, 0.245, 0.665]

Softmax makes the winner win harder. The biggest value gets pushed closer to 1; smaller values get pushed closer to 0.

This is called the softmax function — and you just invented it.

It’s one of the most important functions in machine learning. We’ll see exactly why soon.

Part 4: Sigmoid

Challenge (skip ahead if you can):

Using your softmax function, can you squash a single number into the range $(0, 1)$? Derive the formula and write sigmoid(x).

Got it? Skip to Part 5.

Softmax takes a list and produces probabilities. But what if we only have one number and we want to push it into $(0, 1)$?

Here’s a trick: make it a two-element list by adding a 0:

$\text{softmax}([0,\; x])$

The second element gives us the probability for $x$.

Try it: softmax([0, 3])

  • $e^0 = 1, \quad e^3 \approx 20.09$
  • Second element: $\frac{e^3}{1 + e^3} = \frac{20.09}{21.09} \approx 0.953$

So for any single number $x$, the formula is:

$\sigma(x) = \dfrac{e^x}{1 + e^x}$

This can also be written as:

$\sigma(x) = \dfrac{1}{1 + e^{-x}}$

(Multiply top and bottom by $e^{-x}$ to verify.)

This is the sigmoid function (also called the logistic function). You just derived it from softmax!

Write it in Python and test:

print(sigmoid(100))   # very close to 1
def sigmoid(x):
    return 1 / (1 + math.exp(-x))

print(sigmoid(3))     # 0.953
print(sigmoid(-3))    # 0.047
print(sigmoid(100))   # 1.0 (practically)

Hint: just translate the formula $\frac{1}{1 + e^{-x}}$ directly.

Explore the sigmoid in Desmos. Type this into desmos.com/calculator:

y = 1 / (1 + e^(-(a*x + b)))

Add sliders for $a$ and $b$.

Play with the sliders and answer:

  • What does $a$ control?
  • What does $b$ control?
  • What happens when $a$ is very large?
  • What happens when $a$ is negative?

$a$ controls the steepness. $b$ shifts the curve left or right. As $a \to \infty$, the sigmoid approaches a step function.

Key properties of sigmoid:

  • Output is always between 0 and 1 — perfect for probabilities
  • $\sigma(0) = 0.5$ — the midpoint
  • Large positive $x$ → output near 1
  • Large negative $x$ → output near 0
  • It’s smooth and differentiable everywhere

It maps any real number to a probability. That is exactly what we need for classification.

We need numerical_gradient from the differentiation chapter. Here it is as a helper:

def numerical_gradient(f, params, h=1e-5):
    grads = []
    for i in range(len(params)):
        params_plus = list(params)
        params_plus[i] += h
        params_minus = list(params)
        params_minus[i] -= h
        grads.append((f(*params_plus) - f(*params_minus)) / (2 * h))
    return grads

This computes $\frac{\partial f}{\partial p_i}$ for each parameter by nudging it slightly in both directions.

Part 6: Multiple Features

So far, our model had one input (age). What if $X$ has $d$ features?

Instead of $mx + c$, use a dot product:

$z = w_1 x_1 + w_2 x_2 + \ldots + w_d x_d + b = \mathbf{w} \cdot \mathbf{x} + b$

Then: $\hat{y} = \sigma(z)$

Part 7: Cross-Entropy Loss

Challenge (skip ahead if you can):

Can you think of a loss function that punishes confident wrong predictions much more than MSE? Write cross_entropy(X, y, w, b).

Got it? Skip to Part 8.

MSE works for classification, but let’s think about whether it’s the best choice.

Suppose the true label is $y = 1$ and our model predicts $\hat{y} = 0.001$.

The MSE penalty is $(1 - 0.001)^2 = 0.998$.

Now suppose the model predicts $\hat{y} = 0.01$ — ten times larger. The MSE penalty is $(1 - 0.01)^2 = 0.980$.

That’s barely different! Is MSE harsh enough when we’re very wrong?

What if, instead of squaring the error, we used $-\log(\hat{y})$ when the true label is 1?

Compute these by hand or in Python:

  • $\hat{y} = 0.9$ → $-\log(0.9) = 0.105$ (small penalty — good prediction)
  • $\hat{y} = 0.5$ → $-\log(0.5) = 0.693$
  • $\hat{y} = 0.01$ → $-\log(0.01) = 4.605$ (huge penalty!)
  • $\hat{y} \to 0$ → $-\log(\hat{y}) \to \infty$ (infinite penalty!)

$-\log$ gives a much stronger signal when the model is confidently wrong.

What about when the true label is $y = 0$?

We want to penalize high predictions. What expression goes to $\infty$ as $\hat{y} \to 1$?

$-\log(1 - \hat{y})$

Combining both cases into one formula:

$L = -\left[\; y \cdot \log(\hat{y}) \;+\; (1-y) \cdot \log(1 - \hat{y}) \;\right]$

When $y = 1$: only the first term survives → $-\log(\hat{y})$.
When $y = 0$: only the second term survives → $-\log(1 - \hat{y})$.

This is called binary cross-entropy (or log loss).

Write the cross-entropy loss in Python:

    # YOUR CODE HERE
    pass
def cross_entropy(X, y, w, b):
    y_hat = predict_multi(X, w, b)
    eps = 1e-15  # avoid log(0)
    y_hat = np.clip(y_hat, eps, 1 - eps)
    return -np.mean(y * np.log(y_hat) + (1 - y) * np.log(1 - y_hat))

Hint 1: get predictions, then apply the formula $-\frac{1}{n}\sum[y_i \log(\hat{y}_i) + (1-y_i)\log(1 - \hat{y}_i)]$.

Hint 2: use np.clip(y_hat, 1e-15, 1-1e-15) to avoid log(0).

Part 9: Multi-Class Classification

Challenge (skip ahead if you can):

Extend your classifier to handle more than 2 classes using all 3 Iris species. Write softmax_predict and multi_cross_entropy, and fit with gradient descent.

Got it? Skip to the end.

With 2 classes, we used sigmoid. With $K$ classes, what should we use?

Softmax! Full circle — back to where we started in Part 3.

For each class $k$: $P(y = k) = \text{softmax}(\mathbf{w}_k \cdot \mathbf{x} + b_k)$

We need $K$ sets of weights. Weight matrix $W$ is $(K, d)$, bias $\mathbf{b}$ is $(K,)$.

Load the full Iris dataset (3 classes) and one-hot encode the labels:

iris = load_iris()
X_full = iris.data           # (150, 4)
y_full = iris.target         # 0, 1, or 2

# One-hot encode: label 1 → [0, 1, 0]
def one_hot(y, K):
    oh = np.zeros((len(y), K))
    for i, yi in enumerate(y):
        oh[i, yi] = 1.0
    return oh

Y = one_hot(y_full, 3)      # (150, 3)
print(Y[:3])

Why one-hot? Because with 3 classes, our model outputs 3 probabilities per sample. We need the labels in the same shape.

Write softmax prediction for multi-class:

def softmax_predict(X, W, b):
    # X: (n, d), W: (K, d), b: (K,)
    # return (n, K) matrix of probabilities
    # YOUR CODE HERE
    pass
def softmax_predict(X, W, b):
    Z = X @ W.T + b          # (n, K)
    exp_Z = np.exp(Z - Z.max(axis=1, keepdims=True))
    return exp_Z / exp_Z.sum(axis=1, keepdims=True)

Hint: compute $Z = XW^T + b$, then apply softmax row-wise. Subtract the max per row for numerical stability.

Write the multi-class cross-entropy loss:

$L = -\dfrac{1}{n}\displaystyle\sum_{i=1}^{n}\sum_{k=1}^{K} y_{ik} \log(\hat{y}_{ik})$ 

def multi_cross_entropy(X, Y, W, b):
    # YOUR CODE HERE
    pass
def multi_cross_entropy(X, Y, W, b):
    probs = softmax_predict(X, W, b)
    probs = np.clip(probs, 1e-15, 1.0)
    return -np.mean(np.sum(Y * np.log(probs), axis=1))

Hint: only the terms where $y_{ik} = 1$ contribute — that picks out $\log(\hat{y})$ for the correct class.
