Each symbol gets its own unique bit pattern — we call this a code. Here our code is:

SymbolCodeword
A"0"

This works because no codeword is the start of another codeword. "0" is not a prefix of "1", and vice versa. We can decode the stream left to right, one bit at a time, without ambiguity.

This property is called prefix-free.

What if different symbols had different-length codewords?

Try: A = "0", B = "10", C = "11".

Is this prefix-free? A = "0" is not a prefix of "10" or "11". "10" is not a prefix of "11". Yes — it’s prefix-free!

def encode_var(message):
    scheme = {"A": "0", "B": "10", "C": "11"}
    return "".join(scheme[ch] for ch in message)

def decode_var(bits):
    rev = {"0": "A", "10": "B", "11": "C"}
    result, buf = "", ""
    for b in bits:
        buf += b
        if buf in rev:

            buf = ""
    return result

Compare the two schemes on the message "AAABBC":

SchemeEncodedBits

The variable-length code saved 33% — because A (the most common symbol) gets the shortest codeword.

Key insight: give shorter codes to more frequent symbols.

Quick Check: Why must a code be prefix-free?

A. To make encoding faster    B. To prevent decoding ambiguity    C. To minimize the number of bits    D. To allow symbols of equal length

Answer: B. Without prefix-free, the decoder can’t tell where one codeword ends and the next begins. For example, if A = "0" and B = "00", the string "00" could be "AA" or "B".

Part 4: Inventing Huffman Coding

Here’s an idea. The two rarest symbols should share the longest codewords (they cost the least to make longer). We can group them into one “super-symbol” and repeat.

Build a tree by hand:

  1. Start: A(50%), B(25%), C(20%), D(5%)
  2. Merge two rarest: D(5%) + C(20%) = DC(25%)
  3. Now: A(50%), B(25%), DC(25%)
  4. Merge two rarest: B(25%) + DC(25%) = BDC(50%)
  5. Now: A(50%), BDC(50%)
  6. Merge: root = A + BDC (100%)

Assign bits: left = 0, right = 1 at each fork. Result: A = "0", B = "10", D = "110", C = "111".

def build_huffman_tree(frequencies):
    nodes = [(f, s) for s, f in frequencies.items()]

    while len(nodes) > 1:
        nodes.sort()
        f1, left = nodes.pop(0)
        f2, right = nodes.pop(0)

Part 5: Shannon Entropy — The Limit

Our Huffman code uses 1.70 bits per symbol on average. Is that the best any code can do?

Claude Shannon proved in 1948 that there is an absolute lower bound: the entropy of the source.

$H = - \sum_{s} p(s) \cdot \log_2 p(s)$

No lossless code can average fewer than $H$ bits per symbol.

import math

def entropy(frequencies):
    return sum(-p * math.log2(p)
               for p in frequencies.values() if p > 0)

freq = {"A": 0.50, "B": 0.25, "C": 0.20, "D": 0.05}
print(f"Entropy: {entropy(freq):.4f} bits/symbol")

Hint 1: use math.log2(p).

Hint 2: the formula is $-p \cdot \log_2(p)$ summed over all symbols.

Huffman (1.70) is very close to entropy (1.6855), but not exactly equal. That’s because Huffman must use whole bits — it can’t assign “1.3 bits” to a symbol.

Quick Check: When does Huffman exactly match entropy?

A. When all symbols have equal frequency    B. When all frequencies are powers of $1/2$    C. When there are exactly two symbols    D. Never — it always uses more

Answer: B. When frequencies are powers of $1/2$ ($1/2$, $1/4$, $1/8$, …), $-\log_2(p)$ is a whole number, and Huffman assigns exactly that many bits.
