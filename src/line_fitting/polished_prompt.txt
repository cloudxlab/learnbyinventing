LINE FITTING & CURVE FITTING — Slide Deck Specification
========================================================

This document fully specifies a reveal.js slide presentation for the "Line
Fitting & Curve Fitting" chapter of Learn By Inventing. The presentation is
authored as a content.yaml file and rendered via build.py into slides.html
(reveal.js) and index.html (interactive view). An LLM can recreate the
entire slide deck from this prompt alone.


FORMAT & RENDERING CONTEXT
--------------------------
- The file is `line_fitting/content.yaml` using the content.yaml schema:
  chapter metadata (id, title, intro, mathjax, footer, glossary) followed by
  a `blocks:` array of typed blocks (part, text, exercise, reveal, table).
- Each `text` block becomes one slide in slides.html (via slides.html.j2).
- The slides template wraps each text block's HTML in:
    <section><div class="slide-content">{{ block.text | md }}</div></section>
  and the base CSS sets `.reveal .slide-content { font-size: 0.55em; }`.
- Because of the 0.55em shrinkage, most slides use an inner container with
  `font-size: 1.5em` or `1.6em` to bring text back to readable size.
- reveal.js fragment classes used:
    `fragment`               — hidden, appears on click
    `fragment fade-out`      — starts visible, fades out on its index
    `fragment fade-in-then-out` — appears on its index, disappears on next
  `data-fragment-index="N"` synchronizes multiple elements at the same step.
- The same HTML is also rendered in the interactive (non-slides) view where
  fragments have no effect. A CSS rule in lbi.css hides ?-placeholders:
    `td .fragment.fade-out { display: none; }`

SLIDE 1 — Mystery Box Progressive Reveal
-----------------------------------------
PURPOSE: Hook the learner. Present a mystery function as a black box, then
progressively ask prediction questions. The learner discovers y = 4x − 1.

STRUCTURE: Two-phase layout using absolute positioning scoped to `.reveal`:
  Phase 1 (big intro): visible initially, fades out on fragment-index 0.
  Phase 2 (interactive Q&A): hidden initially, appears on fragment-index 0.

CSS (in a <style> tag at the top of the text block, scoped to .reveal):
  .reveal .phase-container { position: relative; min-height: 18em; }
  .reveal .phase-intro, .reveal .phase-qa {
    position: absolute; top: 0; left: 0; right: 0; font-size: 1.6em;
  }
  .reveal .qa-stack { position: relative; min-height: 5em; }
  .reveal .qa-step  { position: absolute; top: 0; left: 0; right: 0; }

Phase 1 (class="phase-intro fragment fade-out" data-fragment-index="0"):
  - Large centered SVG block diagram (viewBox 300×100, max-width 500px):
    x → [arrow] → [rounded rect with "?" inside] → [arrow] → y
  - Text: "There's a mystery box. You feed it a number x and it gives back
    a number y. You tried it twice:"
  - Table: x=1,y=3 and x=2,y=7

Phase 2 (class="phase-qa fragment" data-fragment-index="0"):
  Two-column flex layout (gap 2em, centered):

  LEFT COLUMN:
  - Smaller SVG block diagram (same design, max-width 280px)
  - Table that grows progressively. Initial rows: x=1→3, x=2→7.
    Then rows added via fragments:
      Row x=3:   always visible, y cell has ?→11 swap at index 1
      Row x=2.5: appears at index 1, y cell has ?→9 swap at index 2
      Row x=2.1: appears at index 2, y cell has ?→7.4 swap at index 3
      Row x=0:   appears at index 3, y cell has ?→−1 swap at index 4
      Row x=0.5: appears at index 4, y cell has ?→1 swap at index 5
      Row x=x₁:  appears at index 5, y cell has ?→4x₁−1 swap at index 6

    Each y-cell "?→value" swap uses this pattern:
      <td>
        <span class="fragment fade-out" data-fragment-index="N">?</span>
        <span class="fragment" data-fragment-index="N">VALUE</span>
      </td>

  RIGHT COLUMN (text-align:left, flex:1, min-width:0):
  - A qa-stack div containing stacked Q&A steps using absolute positioning.
    Each step replaces the previous one in the same visual space.

    Step 0 (fragment fade-out, index 1):
      "How much will y be when x = 3?"

    Step 1 (fragment fade-in-then-out, index 1):
      "✓ y = 11! When x goes up by 1, y goes up by 4."
      "How much when x = 2.5?"

    Step 2 (fragment fade-in-then-out, index 2):
      "✓ y = 9! Half a step in x → half the increase."
      "What about x = 2.1?"

    Step 3 (fragment fade-in-then-out, index 3):
      "✓ y = 7.4! Just 0.1 past x = 2, so 7 + 0.4."
      "Now try x = 0."

    Step 4 (fragment fade-in-then-out, index 4):
      "✓ y = −1! Going back from x = 1 subtracts 4."
      "What about x = 0.5?"

    Step 5 (fragment fade-in-then-out, index 5):
      "✓ y = 1! Halfway between −1 and 3."
      "For any x₁, can you write y = ?"

    Step 6 (fragment, index 6 — final, stays visible):
      Large styled text: "y = 4x − 1"
      "You just discovered a linear function!"

BEHAVIOR: Each click simultaneously reveals the answer in the table (? fades
out, value fades in) and swaps the Q&A text (previous fades out, new fades in).
The table accumulates rows while questions replace each other in-place.

SLIDE 6 — Electronic Thermometer Problem
-----------------------------------------
PURPOSE: Apply the linear model to a real-world problem (temperature from
current). Set up two simultaneous equations.

STRUCTURE: Single column, font-size 1.5em.

- Text: "Do you know how an electronic thermometer works?"
  "When a metal is heated, its resistance changes and that changes the
  electric current through it. We can measure the current and estimate the
  temperature from it."

- Fragment at index 0:
  "We have the following data points:"
  Table: Current (I) | Temperature (T)
         1 mA        | 10 °F
         1.2 mA      | 50 °F
  "Find the equation: T = a × I + b. What are a and b?"

- Fragment at index 1:
  "Put the two values in the equation. You get two equations:"
  Monospace: 10 = a × 1   + b   … (1)
             50 = a × 1.2 + b   … (2)


SLIDE 7 — Solve the Equations
------------------------------
PURPOSE: Walk through solving the two equations.

STRUCTURE: Single column, font-size 1.5em.

- Text: "Now solve them."

- Fragment at index 0: Solution steps in monospace:
  (2) − (1): 40 = 0.2a  →  a = 200
  From (1): b = 10 − 200  →  b = −190

- Fragment at index 1:
  "So, the final equation is:"
  Large centered styled text: T = 200 × I − 190


SLIDE 8 — Generalize to Code: predict() and fit()
---------------------------------------------------
PURPOSE: Codify the by-hand solving into reusable Python functions. The
learner recognizes the pattern and writes general-purpose fit/predict.

STRUCTURE: Single column, font-size 1.5em.

- Text: "You solved two problems by hand. Both times:"
  "Two data points → two equations → solve for a and b."
  "Can you write general Python functions for this?"

- Fragment at index 0: Derivation + code:
  "From y₁ = a × x₁ + b and y₂ = a × x₂ + b, we get:"
  <pre><code> block showing fit() and predict() functions:
    def fit(x1, y1, x2, y2):
        a = (y2 - y1) / (x2 - x1)
        b = y1 - a * x1
        return a, b

    def predict(a, b, x):
        return a * x + b

- Fragment at index 1: Verification with both earlier problems:
  fit(1, 3, 2, 7) → (4, −1)   predict(4, −1, 3) → 11 ✓
  fit(1, 10, 1.2, 50) → (200, −190)   predict(200, −190, 1.5) → 110 ✓


SLIDE 9 — What About More Than Two Points?
--------------------------------------------
PURPOSE: Introduce the real fitting problem — real data has >2 points and
no single line passes through all of them. Motivate error measurement.

STRUCTURE: Two-column flex (table left, scatter plot SVG right), font-size
1.5em, with text fragments below.

- Text: "In the real world, you usually have more than two data points."
- Left: Table with 3 data points: (1,2), (2,5), (3,7)
- Right: SVG scatter plot (viewBox 200×160, max-width 180px) showing:
  Axes (x, y) with 3 blue dots at approximate positions.
  No line drawn (just the points).

- Fragment at index 0:
  "Fitting with the first two points:"
  fit(1, 2, 2, 5) → a = 3, b = −1 → y = 3x − 1

- Fragment at index 1:
  "Does this line work for the third point?"
  At x = 3: predicted = 3×3 − 1 = 8 but actual = 7 — off by 1!

- Fragment at index 2:
  "Try different pairs of points and you get different lines. We need a
  way to measure which line is best."


SLIDE 10 — Residuals & Mean Squared Error
------------------------------------------
PURPOSE: Invent the concept of residual and MSE. Pose the question "how
do we combine errors?" and guide the learner to discover squaring.

STRUCTURE: Single column, font-size 1.5em.

- Text: "For line y = 3x − 1, the residual at each point is the difference
  between actual and predicted:"
- Table: x | Actual | Predicted | Residual
         1 |   2    |     2     |   0
         2 |   5    |     5     |   0
         3 |   7    |     8     |  −1
- "How do we combine these into a single number?"

- Fragment at index 0:
  "If we just sum them, positive and negative errors would cancel out!
  What if we squared them first?"

- Fragment at index 1:
  "(0² + 0² + (−1)²) / 3 = 0.33"
  "This is the Mean Squared Error (MSE)."

- Fragment at index 2:
  "The best fit line is the one with the lowest MSE. Finding it
  efficiently is what gradient descent does."


SLIDE 11 — What If the Pattern Is Curved?
-------------------------------------------
PURPOSE: Show that some data requires curves, not lines. Introduce
polynomials and the overfitting concept.

STRUCTURE: Two-column flex (table left, scatter plot SVG right), font-size
1.5em, with text fragments below.

- Text: "Not all patterns are linear. Consider this data:"
- Left: Table with 4 data points: (0,0), (1,1), (2,4), (3,9)
- Right: SVG scatter plot (viewBox 270×195, max-width 240px) showing:
  Axes (x, y), 4 blue data points.
  Red dashed line (best linear fit y=3x−1) — clearly misses the points.
  Green solid cubic bezier curve (y=x²) — passes through all 4 points.
  The visual contrast between dashed-line and green-curve is immediate.

  SVG coordinates:
  - Data points at (40,170), (100,154), (160,106), (220,26)
  - Dashed line from (60,170) to (238,28)
  - Curve: <path d="M 40,170 C 100,170 160,122 220,26"> (cubic bezier
    approximation of y=x² — passes exactly through all 4 data points)

- Fragment at index 0:
  "No straight line fits this well (dashed). But y = x² fits perfectly
  (green curve)!"
  "This is a polynomial: y = ax² + bx + c"

- Fragment at index 1:
  "More parameters → more flexibility. But too many and the model
  memorizes data instead of learning the pattern. This is called
  overfitting."

  x₁ arrow goes from top-left to middle of box.
  x₂ arrow goes from bottom-left to middle of box.

- Fragment at index 0:
  "Quick question: to find a, b and c, how many pairs of (x₁, x₂, y)

SLIDE 13 — Complex Relationships & LLMs
---------------------------------------
PURPOSE: Show that models can have quadratic and polynomial terms, and that
LLMs are the same idea scaled to billions of parameters.

STRUCTURE: Single column, font-size 1.5em.

- Text: "There could be a complex relationship between inputs and outputs:"
  Centered formula: y = a × x² + b × x + c

- Centered SVG block diagram (viewBox 300×100, max-width 320px):
  x → [ax²+bx+c] → y (same visual style as other diagrams)

- Fragment at index 0:
  "Or there could be a much more complex relationship:"
  Centered formula: y = ax₁² + bx₂² + cx₁ + dx₂ + ex₁x₂ + f
  "Here we have a, b, c, d, e and f — six parameters."

- Fragment at index 1:
  "In case of LLMs, there are 100s of billions of such parameters and the
  equation is much more complex!"


SVG BLOCK DIAGRAM DESIGN SYSTEM
================================
All block diagrams share a consistent visual language:

- viewBox dimensions: 300×100 for single-input, 340×130 for two-input
- Box: <rect> with rx="8", fill="#f5f3ef", stroke="#c8a96e", stroke-width="2"
- Labels inside boxes: Georgia serif, fill="#7a6b3a", text-anchor="middle"
- Input/output labels: Georgia serif, font-size="22", fill="#333"
- Arrows: <line> stroke="#888" stroke-width="2" with <polygon> arrowheads
- Arrow polygon pattern: points="X,Y-5 X+10,Y X,Y+5" fill="#888"
- For the training/inference comparison grid, boxes use colored fills:
    Data: fill="#e3f2fd" stroke="#64b5f6" (blue tones)
    Training: fill="#fff3e0" stroke="#ffb74d" (orange tones)
    Model: fill="#e8f5e9" stroke="#66bb6a" (green tones)
  with smaller font-size (11px labels, 9px sub-labels)


KEY DESIGN PATTERNS
====================

1. Phase swap (Slide 1): Two absolutely-positioned divs; one has
   "fragment fade-out" and the other has "fragment" — both on the same
   data-fragment-index so they swap atomically on click.

2. Table cell ?→value swap: A <td> with two <span>s — one "fragment
   fade-out" with "?", one "fragment" with the value — sharing the same
   data-fragment-index.

3. Q&A text replacement: Stacked divs with absolute positioning. Each uses
   "fragment fade-in-then-out" (appears then disappears on next click) except
   the last which uses plain "fragment" (stays visible). This shows one Q&A
   at a time in the same physical space.

4. Code skeleton→solution swap: Same as phase swap but for code blocks.
   Skeleton has "fragment fade-out", solution has "fragment", same index.

5. Interactive view compatibility: The same HTML works in the non-reveal
   interactive view where all fragments are visible. The CSS rule
   `td .fragment.fade-out { display: none; }` in lbi.css hides the "?"
   placeholders so only values show in the table. Q&A stacking CSS is
   scoped to `.reveal` so in interactive view all Q&A steps just stack
   vertically (all visible, natural flow).


NARRATIVE ARC
=============
1. Hook with mystery → learner predicts → discovers y = 4x − 1
2. Translate discovery to code (Python function)
3. Reflect: "you just did ML" — introduce training vs inference terminology
4. Draw parallel to ChatGPT — same two phases, different scale
5. Confirm generalization works for both simple models and LLMs
6. Generalize formula to y = ax + b
7. Apply to real-world problem (electronic thermometer)
8. Solve the system of equations
9. Generalize to code: predict() and fit() functions
10. Real data has >2 points — fitting is imperfect
11. Invent residuals and MSE — measuring fit quality
12. Curved data needs polynomials — but beware overfitting
13. Extend to multiple inputs (two unknowns → three unknowns)
14. Scale up: quadratic → polynomial → LLMs with billions of parameters

The deck takes the learner from "guess the next number" through coding
predict/fit, inventing MSE, and understanding curve fitting, all the way
to "LLMs are just this idea scaled up" — in 13 slides, each building on
the previous one.
