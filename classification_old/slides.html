Part 1: Scaling Values

Challenge (skip ahead if you can):

Given any list of numbers, write a function that returns a new list where every value is non-negative and the values sum to 1.

def scale(values):
    # return a list that sums to 1
    ...
print(scale([1, 9]))     # [0.1, 0.9]
print(scale([10, 30]))   # [0.25, 0.75]

Got it? Skip to Part 2.

Look at these pairs of numbers and their “scaled” versions:

InputScaled
$(1,\; 9)$$(0.1,\; 0.9)$
$(10,\; 30)$$(0.25,\; 0.75)$
$(1,\; 2,\; 5)$$(0.125,\; 0.25,\; 0.625)$

What rule connects the input to the scaled version?

Before coding — answer on paper:

  • What is $1 + 9$? What is $\frac{1}{10}$?
  • What is $10 + 30$? What is $\frac{10}{40}$?
  • What is $1 + 2 + 5$? What is $\frac{1}{8}$?

The rule: divide each value by the sum of all values.

$\text{scaled}_i = \dfrac{x_i}{\sum_j x_j}$

Now write it in Python:

def scale(values):
    # YOUR CODE HERE
    pass
def scale(values):
    total = sum(values)
    return [v / total for v in values]

Hint: compute the sum(values) first, then divide each element.

print(scale([1, 9]))       # [0.1, 0.9]
print(scale([10, 30]))     # [0.25, 0.75]
print(scale([1, 2, 5]))    # [0.125, 0.25, 0.625]
print(sum(scale([3,7,2]))) # 1.0

Part 2: Making Big Bigger

Challenge (skip ahead if you can):

Write a function that takes any list of numbers, makes large values close to 1 and small values close to 0, with the total summing to 1.

def decisive_scale(values):
    # return "decisive" probabilities
    ...

Got it? Skip to Part 3.

Try scale([1, 5]). What do you get?

$[0.167,\; 0.833]$

That’s okay, but not very decisive. If $5$ is much bigger than $1$, shouldn’t the result be closer to $(0.01,\; 0.99)$?

How could you make big values bigger and small values smaller before scaling?

Brainstorm — there is no single right answer. Try a few ideas:

  • Square them? scale([1**2, 5**2]) = scale([1, 25]) → $[0.038,\; 0.962]$. Better!
  • Cube them? scale([1**3, 5**3]) = scale([1, 125]) → $[0.008,\; 0.992]$. Even more decisive.
  • But what about negative numbers? $(-3)^2 = 9$ — that flips the ordering!

We need a function that is always positive and grows fast for large inputs. What function does that?

The exponential function: $e^x$.

  • Always positive (even for negative $x$)
  • Grows very fast: $e^1 \approx 2.7$, $e^5 \approx 148.4$
  • Preserves order: if $a > b$ then $e^a > e^b$

Try it in Python:

from math import exp
print(scale([exp(1), exp(5)]))
# compare with scale([1, 5])

$\text{scale}([e^1, e^5]) \approx [0.018,\; 0.982]$ — much more decisive!

Part 3: Softmax

Challenge (skip ahead if you can):

Write softmax(values) from scratch — it should turn any list of numbers into probabilities that sum to 1, with larger inputs getting much larger probabilities.

def softmax(values):
    ...
print(softmax([1, 2, 5]))  # large weight on 5

Got it? Skip to Part 4.

Putting your two discoveries together:

  1. Apply $e^x$ to each value (makes big bigger, stays positive)
  2. Scale so they sum to 1 (divide by total)

This two-step process has a name: softmax.

$\text{softmax}(x_i) = \dfrac{e^{x_i}}{\displaystyle\sum_j e^{x_j}}$

Write it in Python:

from math import exp

def softmax(values):
    # YOUR CODE HERE
    pass
from math import exp

def softmax(values):
    exps = [exp(v) for v in values]
    total = sum(exps)
    return [e / total for e in exps]

Hint: first compute [exp(v) for v in values], then divide each by the sum.

print(softmax([1, 2, 5]))
# [0.018, 0.047, 0.935]  — 5 dominates!
print(sum(softmax([1, 2, 5])))  # 1.0

Try softmax on different inputs and notice the pattern:

print(softmax([0, 0, 0]))   # equal inputs → ?
print(softmax([1, 1, 1]))   # still equal → ?
print(softmax([-1, 0, 1]))  # spread out → ?
print(softmax([10, 20]))    # big gap → ?

Key insight: softmax turns any list of numbers into probabilities — always positive, always sum to 1. Equal inputs give equal probabilities; bigger gaps give more decisive results.

Part 4: Sigmoid

Challenge (skip ahead if you can):

What if you have just one number and need to map it to a value between 0 and 1? Can you derive a formula using softmax?

def sigmoid(x):
    # map any number to (0, 1)
    ...

Got it? Skip to Part 5.

Softmax needs at least two numbers. But what if you only have one?

Trick: make it two numbers by pairing your value $x$ with $0$.

Apply softmax to $[0,\; x]$:

$\text{softmax}([0,\; x]) = \left[\;\dfrac{e^0}{e^0 + e^x},\;\; \dfrac{e^x}{e^0 + e^x}\;\right] = \left[\;\dfrac{1}{1 + e^x},\;\; \dfrac{e^x}{1 + e^x}\;\right]$

Try it: softmax([0, 3]). The second element is our answer.

That second element, $\dfrac{e^x}{1 + e^x}$, can also be written as:

$\sigma(x) = \dfrac{1}{1 + e^{-x}}$

Verify: multiply top and bottom of $\dfrac{e^x}{1 + e^x}$ by $e^{-x}$.

This function is called the sigmoid. It maps any number to a value between 0 and 1.

Write the sigmoid in Python:

from math import exp

def sigmoid(x):
    # YOUR CODE HERE
    pass
from math import exp

def sigmoid(x):
    return 1 / (1 + exp(-x))

Hint: use the formula $\sigma(x) = \frac{1}{1 + e^{-x}}$.

print(sigmoid(0))    # 0.5  (midpoint)
print(sigmoid(5))    # ≈ 0.993
print(sigmoid(-5))   # ≈ 0.007
print(sigmoid(100))  # ≈ 1.0

Go to desmos.com/calculator and plot:

$y = \dfrac{1}{1 + e^{-(ax+b)}}$

Add sliders for $a$ and $b$. Try changing them.

What does $a$ control?

$a$ controls the steepness of the S-curve. Larger $|a|$ → sharper transition.

What does $b$ control?

$b$ controls the horizontal shift. The midpoint ($y = 0.5$) moves to $x = -b/a$.

Part 6: Why Lines Fail

What do you notice about the linear regression line?

  • It goes below 0 for young ages
  • It doesn’t capture the “step” shape at all
  • Predictions can be negative or greater than 1

For classification we need predictions between 0 and 1 (they represent probabilities).

What function maps any number to the range $(0, 1)$?

The sigmoid you just invented!

Instead of predicting $y = mx + c$ (which can be anything), predict:

$\hat{y} = \sigma(mx + c)$

The linear part $mx + c$ can be any real number. The sigmoid squashes it into $(0, 1)$.

Now $\hat{y}$ is a probability: how likely is this person a teenager?

The parameters $m$ and $c$ control the steepness and position of the S-curve — just like you explored in Desmos!

def numerical_gradient(f, params, h=1e-5):
    grads = []
    for i in range(len(params)):
        params_plus = list(params)
        params_plus[i] += h
        grads.append((f(*params_plus) - f(*params)) / h)
    return grads

Instead of $mx + c$, use a dot product:

$z = w_1 x_1 + w_2 x_2 + \ldots + w_d x_d + b = \mathbf{w} \cdot \mathbf{x} + b$

Part 9: Cross-Entropy Loss

Challenge (skip ahead if you can):

Can you think of a better loss function than MSE for classification? Write cross_entropy(X, y, w, b).

Got it? Skip to Part 10.

MSE works, but let’s think about whether it’s the best choice.

Suppose the true label is $y = 1$ and our model predicts $\hat{y} = 0.001$.

The MSE penalty is $(1 - 0.001)^2 = 0.998$.

Now suppose the model predicts $\hat{y} = 0.01$ — ten times larger. The MSE penalty is $(1 - 0.01)^2 = 0.980$.

That’s barely different! Is MSE harsh enough when we’re very wrong?

What if, instead of squaring the error, we used $-\log(\hat{y})$ when the true label is 1?

  • $\hat{y} = 0.9$ → $-\log(0.9) = 0.105$ (small penalty — good prediction)
  • $\hat{y} = 0.5$ → $-\log(0.5) = 0.693$
  • $\hat{y} = 0.01$ → $-\log(0.01) = 4.605$ (huge penalty!)
  • $\hat{y} \to 0$ → $-\log(\hat{y}) \to \infty$ (infinite penalty!)

$-\log$ gives a much stronger signal when the model is confidently wrong.

What about when the true label is $y = 0$?

We want to penalize high predictions. What expression goes to $\infty$ as $\hat{y} \to 1$?

$-\log(1 - \hat{y})$

Combining both cases into one formula:

$L = -\left[\; y \cdot \log(\hat{y}) \;+\; (1-y) \cdot \log(1 - \hat{y}) \;\right]$

When $y = 1$: only the first term survives → $-\log(\hat{y})$.
When $y = 0$: only the second term survives → $-\log(1 - \hat{y})$.

This is called binary cross-entropy (or log loss).

Write the cross-entropy loss in Python:

def cross_entropy(X, y, w, b):
    # YOUR CODE HERE
    pass
def cross_entropy(X, y, w, b):
    y_hat = predict_multi(X, w, b)
    eps = 1e-15  # avoid log(0)
    y_hat = np.clip(y_hat, eps, 1 - eps)
    return -np.mean(y * np.log(y_hat) + (1 - y) * np.log(1 - y_hat))

Hint 1: get predictions, then apply the formula $-\frac{1}{n}\sum[y_i \log(\hat{y}_i) + (1-y_i)\log(1 - \hat{y}_i)]$.

Hint 2: use np.clip(y_hat, 1e-15, 1-1e-15) to avoid log(0).

Part 11: Multi-Class Classification

Challenge (skip ahead if you can):

Extend your classifier to handle more than 2 classes using all 3 Iris species. Write softmax_predict and multi_cross_entropy.

Got it? Skip to the end.

With 2 classes, we used sigmoid. With $K$ classes, what should we use?

Softmax! Full circle — back to where we started.

For each class $k$: $P(y = k) = \text{softmax}(\mathbf{w}_k \cdot \mathbf{x} + b_k)$

We need $K$ sets of weights. Weight matrix $W$ is $(K, d)$, bias $\mathbf{b}$ is $(K,)$.

Load the full Iris dataset (3 classes) and one-hot encode the labels:

iris = load_iris()
X_full = iris.data           # (150, 4)
y_full = iris.target         # 0, 1, or 2

# One-hot encode: label 1 → [0, 1, 0]
def one_hot(y, K):
    oh = np.zeros((len(y), K))
    for i, yi in enumerate(y):
        oh[i, yi] = 1.0
    return oh

Y = one_hot(y_full, 3)      # (150, 3)
print(Y[:3])

Write softmax prediction for multi-class:

def softmax_predict(X, W, b):
    # X: (n, d), W: (K, d), b: (K,)
    # return (n, K) matrix of probabilities
    # YOUR CODE HERE
    pass
def softmax_predict(X, W, b):
    Z = X @ W.T + b          # (n, K)
    exp_Z = np.exp(Z - Z.max(axis=1, keepdims=True))
    return exp_Z / exp_Z.sum(axis=1, keepdims=True)

Hint: compute $Z = XW^T + b$, then apply softmax row-wise. Subtract the max per row for numerical stability.

Write the multi-class cross-entropy loss:

$L = -\dfrac{1}{n}\displaystyle\sum_{i=1}^{n}\sum_{k=1}^{K} y_{ik} \log(\hat{y}_{ik})$ 

def multi_cross_entropy(X, Y, W, b):
    # YOUR CODE HERE
    pass
def multi_cross_entropy(X, Y, W, b):
    probs = softmax_predict(X, W, b)
    probs = np.clip(probs, 1e-15, 1.0)
    return -np.mean(np.sum(Y * np.log(probs), axis=1))

Hint: only the terms where $y_{ik} = 1$ contribute — that picks out $\log(\hat{y})$ for the correct class.

Fit with gradient descent on the full Iris dataset:

W = np.zeros((K, d))
b = np.zeros(K)
