Part 1: Finding the Nearest Neighbor

Challenge (skip ahead if you can):

Write knn_predict(point, dataset, k) that classifies a new point by finding its k nearest labeled neighbors and taking a majority vote.

Already got it? Skip to the end.

Imagine you just moved to a new city. You find a fruit you’ve never seen and want to know if it’s an apple or an orange.

You could measure its weight and color, then compare those numbers to fruits you already know. The closest match is your best guess.

That’s the whole idea. Let’s build it.

import math

def distance(a, b):
    return math.sqrt(sum((x - y) ** 2 for x, y in zip(a, b)))

print(distance([0, 0], [3, 4]))      # 5.0
print(distance([1, 2, 3], [4, 6, 3]))  # 5.0

def find_k_nearest(point, labeled_data, k):
    by_dist = sorted(labeled_data,
                     key=lambda item: distance(point, item[0]))
    return by_dist[:k]

def majority_vote(neighbors):
    counts = {}
    for _, label in neighbors:
        counts[label] = counts.get(label, 0) + 1
    return max(counts, key=counts.get)

test = [([3,4],"apple"), ([6,1],"orange"), ([7,1],"orange")]
print(majority_vote(test))  # "orange" (2 votes vs 1)

Quick Check: You have 3 nearest neighbors with labels ["apple", "apple", "orange"]. What does majority vote predict?

Answer: A. Apple wins 2–1. Each neighbor gets one vote regardless of its distance.

def knn_accuracy(dataset, k):
    correct = 0
    for i in range(len(dataset)):
        test_point, true_label = dataset[i]
        train = dataset[:i] + dataset[i+1:]
        if knn_predict(test_point, train, k) == true_label:
            correct += 1
    return correct / len(dataset)

print(knn_accuracy(dataset, 3))  # 1.0 (all correct)

Hint 1: loop through each index i. The training set is everything except index i.

Hint 2: dataset[:i] + dataset[i+1:] gives you all items except the $i$-th one.

Points near the boundary between classes are harder to classify. Different values of $k$ handle these differently.

Quick Check: For a two-class problem, why is an odd value of $k$ preferred?

A. Odd numbers compute faster    B. Avoids ties in the majority vote    C. Odd $k$ is always more accurate    D. Even $k$ causes errors

Answer: B. With two classes and an odd $k$, one class always has strictly more votes. Even $k$ can produce a tie like 2–2.

Part 4: Choosing K and Distance

What happens as $k$ changes?

$k$Behavior
1Copies the nearest label exactly — memorizes noise
3–7Smooths out outliers — usually a sweet spot
$n$Always predicts the most common class — ignores the data

$k = 1$ overfits (too sensitive to noise). Large $k$ underfits (too smooth, loses local patterns). The best $k$ is somewhere in between.

def manhattan_distance(a, b):
    return sum(abs(x - y) for x, y in zip(a, b))

Quick Check: K-NN’s biggest weakness at scale is:

A. It can only handle two classes    B. It needs to be retrained when new data arrives    C. It computes distance to every training point for each prediction    D. It can only work with numbers, not categories

Answer: C. With $n$ training points and $d$ dimensions, each prediction costs $O(nd)$. For millions of points, that gets slow. (Techniques like KD-trees help.)
