a?  does NOT match: a, abc

Part 3: The * Wildcard

Challenge (skip ahead if you can):

Write match(pat, text) supporting ? and * (zero or more characters). Then write find_matching for shell-style globbing.

Got it? Skip to Part 4.

* matches zero or more characters:

a*b    matches: ab, axyzb, a123b
a*b*c  matches: abc, abbbc, a1b1c

Before coding: pattern a*b, text "axyzb". The a matches. Now * faces "xyzb". How many characters should it swallow?

You can’t know yet — it depends on what comes after the star. So try both options:

  1. * swallows nothing → try rest of pattern against current text
  2. * swallows one more char → star stays, try against text[1:]

If either branch succeeds, the match succeeds. This is backtracking.

def match(pat, text):
    if not pat:
        return not text
    if pat[0] == '*':
        return (match(pat[1:], text) or
                (len(text) > 0 and match(pat, text[1:])))
    if not text:
        return False
    if pat[0] == '?' or pat[0] == text[0]:
        return match(pat[1:], text[1:])
    return False

print(match("*.txt", "notes.txt"))  # True
print(match("a*b*c", "aXXbYc"))    # True
print(match("a*b", "abc"))          # False

Hint 1: handle * first. Two branches with or: match(pat[1:], text) or match(pat, text[1:]).

Hint 2: guard the second branch — only swallow a char if text is not empty.

Quick Check: Pattern a*b against "axxbyyb". A greedy * first tries to consume everything. Why does the matcher need backtracking?

A. * can only match letters    B. The greedy * eats xxbyyb, leaving nothing for the final b — it must back up    C. Duplicate b characters cause confusion    D. * must be at the end

Answer: B. The * greedily eats everything, but then b has nothing left. The matcher must back up and let * consume fewer characters until the rest can match.

Part 4: Regular Expressions

What you invented is the core idea behind regular expressions. Python’s re module speaks a richer dialect:

.        any single character        (your ?)
*        previous thing, 0+ times    (not your glob *)
+        previous thing, 1+ times
[aeiou]  any ONE character from set
[0-9]    any ONE digit
[^xyz]   any char NOT in the set
{4}      previous thing, exactly 4×
\.       a literal dot (escaped)
^  $     start / end of line

Key twist: regex * means “repeat the previous item” — so your glob a*b becomes regex a.*b.

import re
re.search(pattern, text)   # first match, or None
re.findall(pattern, text)  # list of all matches

STRICT_DATE = (
    r"(0[1-9]|[12][0-9]|3[01])"  # day
    r"[/-]"
    r"(0[1-9]|1[0-2])"           # month
    r"[/-]"
    r"[0-9]{4}"                   # year
)

def is_valid_date(s):
    return bool(re.fullmatch(STRICT_DATE, s))

print(is_valid_date("05/07/1980"))  # True
print(is_valid_date("99/07/1980"))  # False

Hint 2: month: (0[1-9]|1[0-2]). Use re.fullmatch so the entire string must match.

def find_urls(text):
    return re.findall(r'https?://[^\s"\')\]]+', text)

def domain_counts(urls):
    counts = {}
    for url in urls:
        domain = url.split("/")[2]
        counts[domain] = counts.get(domain, 0) + 1
    return counts

line = 'GET /page "https://example.com/path" "http://test.org"'
print(find_urls(line))
# ["https://example.com/path", "http://test.org"]

Hint: URL starts with https?:// and continues until whitespace or a quote: [^\s"')\]]+. Domain is url.split("/")[2].

Quick Check: What does <b>.*</b> match in <b>hello</b> and <b>world</b>?

A. Just <b>hello</b>    B. Two separate matches    C. The entire string (greedy .* stretches to the last </b>)    D. Nothing

Answer: C. .* is greedy — it eats as many characters as possible. Use .*? (non-greedy) to match each bold section separately.

The branching trick in your * matcher — try both, succeed if either succeeds — is called backtracking. It is the same idea that solves mazes, Sudoku, and N-Queens, and it is how simple regex engines work.
