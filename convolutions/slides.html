Part 1: What Is an Image?

Before anything else — pencil and paper.

Here is a 5×5 grid of numbers. Each number is a brightness value: 0 = black, 255 = white.

  0    0    0    0    0
  0  255  255  255    0
  0  255    0  255    0
  0  255  255  255    0
  0    0    0    0    0

Close your eyes and picture it. What shape do you see?

A white square outline (hollow rectangle) on a black background. That’s all an image is to a computer — a grid of numbers.

Before coding: A camera takes a color photo that is 480 pixels wide and 360 pixels tall.

When you load it into Python as a NumPy array and print .shape, what three numbers will you see? Write your prediction down before running any code.

Hint: NumPy puts height first, then width. The third number represents something about color…

(360, 480, 3) — height, width, and 3 color channels. What are those 3 channels?

Print the value at one pixel:

print(img[0, 0])   # e.g., [143, 98, 72]

Three numbers per pixel. What do they mean?

They’re (Red, Green, Blue). Every color you’ve ever seen on a screen is a mix of these three. [255, 0, 0] is pure red. [0, 0, 0] is black. [255, 255, 255] is white.

A grayscale image needs only one number per pixel (0 = black, 255 = white):

gray = np.array(Image.open("cat.jpg").convert("L"))
print(gray.shape)   # (360, 480) — no third dimension

Part 2: Inventing Grayscale

Before coding — think first.

A pixel has R=200, G=50, B=50. You need a single gray value.

Should it be closer to 200 (because red is high) or closer to 100 (the average of all three)?

Neither answer is “wrong” — it depends on what you mean by brightness. Let’s try the simplest idea first and see if it’s good enough.

Now experiment. Display your result. It looks … okay. But try this thought experiment:

Imagine a pure green pixel [0, 200, 0] and a pure red pixel [200, 0, 0]. Both produce the same gray value: $(0+200+0)/3 = (200+0+0)/3 = 67$.

But does green look as bright as red to your eyes?

Try it — look at a green square and a red square of equal RGB magnitude on your screen. Green looks much brighter. Our simple average treats them the same, but human vision doesn’t.

Exercise 2.2: Can you find weights $w_R, w_G, w_B$ (that sum to 1) so that the grayscale conversion matches how bright things look to your eyes?

def gray_weighted(color_arr, wr, wg, wb):
    """Convert to gray using custom weights."""
    r = color_arr[:,:,0].astype(float)
    g = color_arr[:,:,1].astype(float)
    b = color_arr[:,:,2].astype(float)
    return (wr*r + wg*g + wb*b).astype(np.uint8)

Hint

Green should get the biggest weight (eyes are most sensitive to green), blue the smallest. Try 0.3, 0.6, 0.1 as a starting point.

If you landed near R×0.3 + G×0.6 + B×0.1, you just rediscovered the formula that TV engineers settled on in 1953:

$\text{gray} = 0.299\,R + 0.587\,G + 0.114\,B$

This is the ITU-R BT.601 luminosity standard. It matches human vision because our eyes have far more green-sensitive cone cells than red or blue ones.

For the rest of this chapter, we’ll use this as our rgb_to_gray:

def rgb_to_gray(color_arr):
    return (0.299 * color_arr[:,:,0] +
            0.587 * color_arr[:,:,1] +
            0.114 * color_arr[:,:,2]).astype(np.uint8)

Quick Check: Why does the standard formula give green the largest weight (0.587)?

A. Green light has the most energy
B. The human eye is most sensitive to green
C. There are more green pixels in most images
D. It’s arbitrary — any weights work equally well

Answer: B. Human vision has peak sensitivity in the green range, so green contributes more to perceived brightness.

Part 4: Growing Images

Before coding — think on paper.

You have two adjacent pixels with values 100 and 200. You need to insert a new pixel between them.

What value would look most natural?

Now: what if you need to insert two pixels between them, creating three equal steps from 100 to 200?

You’re doing interpolation — filling in values between known points. 100 → 125 → 150 → 175 → 200 creates smooth, even spacing.

Look at the result. Every pixel became a blocky 2×2 square. Edges that were smooth now look like staircase steps.

Can you make the transitions smooth instead? Remember the idea from the paper exercise — insert values between the neighbors.

First, the building block — linear interpolation:

def lerp(a, b, t):
    """Blend: t=0 gives a, t=1 gives b, t=0.5 gives midpoint."""
    return a + t * (b - a)

lerp(100, 200, 0.0)   # 100
lerp(100, 200, 0.5)   # 150
lerp(100, 200, 1.0)   # 200

Part 6: Finding Edges

Before coding — paper exercise.

Here’s a row of pixels:

  50   50   50  |  200  200  200

There’s clearly an edge between the dark region (50) and the bright region (200). How would you compute a number that’s big where there’s an edge and small where it’s flat?

Idea: For each pixel, subtract its left neighbor from its right neighbor. Where the image is flat, the difference is near zero. At an edge, it’s large.

position:   0    1    2    3    4    5
 values:   50   50   50  200  200  200
right-left: 0    0  150  150    0    —

The big numbers (150) mark the edge!

Stop and notice something.

Look at your two functions so far:

  • smooth: slides a 3×3 window, averages the patch → removes noise
  • find_vertical_edges: slides a window, computes right minus left → finds edges

Both slide a small window across the image. Both compute a weighted combination of the pixels in the window. The only difference is the weights:

Smoother weights:          Edge-finder weights:
  1/9  1/9  1/9              -1   0   1
  1/9  1/9  1/9               0   0   0
  1/9  1/9  1/9               0   0   0

Part 8: Padding & the Full Pipeline

Before coding: Your conv returns a smaller image. A 100×100 image with a 3×3 kernel gives … what size?

98×98. You lose one pixel on each side because the 3×3 window can’t center on the border pixels.

General formula: input size $N$ with kernel size $K$ gives output size $N - K + 1$.

How could you get the output to be the same size as the input?

Idea: add extra pixels (zeros) around the border before convolving. How many do you need on each side for a 3×3 kernel? For a 5×5 kernel?

sx = conv_same(gray.astype(float), sobel_x)
sy = conv_same(gray.astype(float), sobel_y)
raw_edges = np.sqrt(sx**2 + sy**2)
edges_B = conv_same(raw_edges, np.ones((3,3)) / 9.0)

The big insight.

In all your experiments, you chose the kernel weights: all-1/9 for blur, Sobel for edges, your custom designs.

What if a computer could learn the best weights from examples?

That’s exactly what a Convolutional Neural Network (CNN) does. It starts with random kernel weights and adjusts them using gradient descent until the kernels produce features that solve the task — detecting cats, reading handwriting, diagnosing X-rays.

The conv function you wrote is the core operation of modern computer vision.
