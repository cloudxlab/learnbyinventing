# ON SCREEN:
# Rules of thumb for reading code: Pattern Big O No loop fixed operations O(1) Single loop over n items O(n) Two separate loops (not nested) O(n) [math] Loop that halves range each step O(log n) Loop of n, each does O(log n) work O(n log n) Loop inside a loop, both over n O([math])
# ---
Here's a handy cheat sheet for reading code and spotting its Big O. You've already worked out most of these yourself, so this is really a summary of your own discoveries. No loop at all means constant time. One loop over n items is linear. Two loops side by side are still linear. A loop that halves its range each step is logarithmic. Put a log-sized job inside a loop of n and you get n log n. And a loop inside a loop gives you n squared. Look at the code, ask what's looping over what, and the answer usually jumps out.
