# Going further: O(2ⁿ) — exponential: The number of subsets of a set with n items. Algorithms that try every subset are O(2ⁿ) — feasible for n ≤ 20, impossible for n = 100. O(n!) — factorial: The number of permutations. Even worse than exponential. Amortized analysis: Some operations are usually fast but occasionally slow (like appending to a Python list that needs to resize). Amortized analysis averages the cost over many operations. P vs NP: The biggest open question in computer science — are there problems where checking a solution is easy but finding one is fundamentally hard? A million-dollar prize awaits the answer.
# ---
You've just invented a whole way of thinking about how algorithms grow, and there's a lot more to explore. Some algorithms try every possible subset, and that doubles with each new item. It's fine for twenty items, but hopeless for a hundred. Others try every ordering, which grows even faster. There's also a clever idea about averaging out the occasional slow step. And there's a famous open question: is checking an answer really easier than finding one? Pick whichever sparks your curiosity and keep inventing.
