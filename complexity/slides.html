Part 1: How Long Does It Take?

Challenge (skip ahead if you can):

sum_list doubles when n doubles — linear. has_pair quadruples when n doubles — quadratic.

On a million items, the linear function takes ~1 second. The quadratic one takes ~11 days. Understanding which category your algorithm falls into is one of the most important skills in programming.

But timing is noisy — it depends on your computer, what else is running, even background updates. Can we predict growth without running the code?

Yes: count the key operations.

Now do the same for has_pair_with_sum. Count the number of comparisons in the inner loop:

def has_pair_counted(lst, target):
    count = 0
    for i in range(len(lst)):
        for j in range(i + 1, len(lst)):
            count += 1
            if lst[i] + lst[j] == target:
                return count
    return count

print(has_pair_counted(list(range(10)), -1))    # ?
print(has_pair_counted(list(range(100)), -1))   # ?
print(has_pair_counted(list(range(1000)), -1))  # ?
print(has_pair_counted(list(range(10)), -1))    # 45
print(has_pair_counted(list(range(100)), -1))   # 4950
print(has_pair_counted(list(range(1000)), -1))  # 499500

# 45 / 10  = 4.5     45 / 100  = 0.45
# 4950 / 100 = 49.5  4950 / 10000 = 0.495
# count / n grows;    count / n² stays constant!
# count ≈ n²/2

Hint: divide each count by n, then by $n^2$. Which ratio stays roughly constant?

The count is $n(n-1)/2 \approx n^2/2$. Does the “÷2” matter?

At $n = 1{,}000{,}000$: count $\approx 500{,}000{,}000{,}000$ (500 billion). Whether it’s $n^2$ or $n^2/2$ — it’s still astronomically large. The “/2” is irrelevant compared to the $n^2$.

We care about the growth rate, not the exact count. Whether it’s $n$, $2n$, or $100n$ — they all grow linearly. Whether it’s $n^2$, $n^2/2$, or $5n^2 + 3n$ — they all grow quadratically.

Quick Check: A single loop runs n times, doing 5 operations per iteration. Total = $5n$. How does it grow?

A. Grows like 5 (constant)    B. Grows like n (linear)    C. Grows like 5n    D. Grows like $n^2$

Answer: B. $5n$ grows linearly. The 5 is a constant multiplier — doubling n still doubles the work.

Part 3: Inventing a Notation

You’ve seen linear ($n$) and quadratic ($n^2$). But there are more growth families. Count the steps in a binary search:

def search_counted(lst, target):
    count = 0
    lo, hi = 0, len(lst) - 1
    while lo <= hi:
        count += 1
        mid = (lo + hi) // 2
        if lst[mid] == target:   return count
        elif lst[mid] < target:  lo = mid + 1
        else:                    hi = mid - 1
    return count

for n in [10, 100, 1000, 10000, 100000]:
    steps = search_counted(list(range(n)), -1)
    print(f"n={n:>6d}  steps={steps}")
# n=    10  steps=4
# n=   100  steps=7
# n=  1000  steps=10
# n= 10000  steps=14
# n=100000  steps=17

# n grew 10000x but steps only grew from 4 to 17.
# What function grows this slowly?  log(n)!

Hint: n went from 10 to 100,000 (10,000×) but steps barely changed. Each doubling of n adds just 1 step.

The notation you just invented is called Big O notation. Computer scientists write:

$$O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(n^3) < O(2^n)$$

$O(f(n))$ means “grows at most as fast as $f(n)$.” When we say an algorithm is $O(n^2)$, we mean: as the input gets large, the time grows no faster than some constant times $n^2$.

The formal notation was introduced by Paul Bachmann in 1894 — but the idea is exactly what you discovered: classify algorithms by their growth family, ignore the constants.

Part 4: Analysing Real Code

What is the Big O of each function? Don’t run them — read the code.

def find_max(lst):          # A
    best = lst[0]
    for x in lst:
        if x > best: best = x
    return best

def double_scan(lst):       # B
    total = 0
    for x in lst: total += x
    for x in lst: total += x * 2
    return total

def all_pairs(lst):         # C
    pairs = []
    for i in range(len(lst)):
        for j in range(i+1, len(lst)):
            pairs.append((lst[i], lst[j]))
    return pairs

def get_first(lst):         # D
    return lst[0]

A: O(n) — one loop.   B: O(n) — $n + n = 2n$, drop constant.   C: O($n^2$) — nested loop.   D: O(1) — no loop.

Quick Check: What is the Big O of this function?

def mystery(lst):
    total = 0
    for x in lst:
        total += x
    for x in lst:
        for y in lst:
            total += x * y
    return total

A. O(n) — because the first loop is O(n)    B. O($n + n^2$)    C. O($n^2$) — the nested loop dominates    D. O($n^3$) — three loops total

Answer: C. First loop is O(n), nested pair is O($n^2$). Total is $n + n^2$ but the fastest-growing term is $n^2$.

Best, worst, and average case. Consider linear search:

def linear_search(lst, target):
    for i in range(len(lst)):
        if lst[i] == target:
            return i
    return -1
  • Best case: target is first → 1 comparison
  • Worst case: target is last or missing → n comparisons
  • Average: target is equally likely at any position → $n/2$ comparisons

When someone says “linear search is O(n)” without qualification, they mean the worst case.

def classify(f, sizes=(100, 200, 400, 800)):
    counts = [f(n) for n in sizes]
    ratios = [counts[i+1]/counts[i]
              for i in range(len(counts)-1)
              if counts[i] > 0]
    r = sum(ratios) / len(ratios) if ratios else 1
    if r < 1.1:   return "O(1)"
    if r < 1.5:   return "O(log n)"
    if r < 2.5:   return "O(n)"
    if r < 3.0:   return "O(n log n)"
    return "O(n^2)"

Part 5: Memory Complexity

Time isn’t the only resource. Memory matters too. How much extra memory does each function create (beyond the input)?

def sum_in_place(lst):      # A: one variable
    total = 0
    for x in lst: total += x
    return total

def make_copy(lst):         # B: new list of n items
    return [x for x in lst]

def make_matrix(n):         # C: n rows × n columns
    return [[0]*n for _ in range(n)]

A: O(1) space — just total, no matter how big lst is.

B: O(n) space — a new list with n items.

C: O($n^2$) space — $n \times n$ items.

The time–space tradeoff. Two ways to check for duplicates:

def has_dup_loops(lst):    # Approach 1: nested loops
    for i in range(len(lst)):
        for j in range(i+1, len(lst)):
            if lst[i] == lst[j]: return True
    return False

def has_dup_set(lst):      # Approach 2: use a set
    seen = set()
    for x in lst:
        if x in seen: return True
        seen.add(x)
    return False
TimeSpace
Nested loopsO($n^2$)O(1)
SetO(n)O(n)

Approach 2 spends memory to save time. This tradeoff appears everywhere in CS.

Quick Check: A function takes n numbers and creates a dictionary mapping each to its square. What is the space complexity?

A. O(1) — dictionaries are always constant    B. O(n) — one entry per input element    C. O($n^2$)    D. O(log n)

Answer: B. The dictionary stores n key-value pairs. Extra memory grows proportionally to n.
