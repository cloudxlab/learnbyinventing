Part 1: Factorial — Your First Recursive Function

Challenge (skip ahead if you can):

Write factorial(n) that returns n! using recursion (no loops). For example: factorial(5) → 120, factorial(0) → 1.

Already got it? Skip to Part 2.

factorial(4) means 4 * 3 * 2 * 1 = 24. By definition, factorial(0) = 1.

Before coding:

  1. Write factorial(4) as 4 * factorial(3). What is factorial(3) in terms of factorial(2)? Keep going until you hit a number whose factorial you just know.
  2. What is the smallest n where you can answer without calling factorial again? That’s the base case.
  3. For every other n, how do you express factorial(n) using factorial(n-1)? That’s the recursive case.
  • Base case: factorial(0) = 1
  • Recursive case: factorial(n) = n * factorial(n - 1)

Hint 1: start with if n == 0: return 1.

Hint 2: otherwise return n * factorial(n - 1).

What happens if you call factorial(-1)?

Walk through it: factorial(-1) calls factorial(-2), which calls factorial(-3)… It never reaches n == 0!

Python raises RecursionError: maximum recursion depth exceeded.

The base case is what stops the recursion. Without it (or if the recursive step never reaches it), the function calls itself forever.

Quick Check: What is the role of the base case in a recursive function?

A. It makes the function run faster

B. It tells Python to use a loop instead

C. It provides the stopping condition — the simplest case answered directly, without another recursive call

D. It handles invalid inputs like negative numbers

Answer: C. The base case is the stopping condition — the simplest input answered directly. Without it, recursion never ends.

Part 5: HCF — Euclid’s Algorithm

Challenge (skip ahead if you can):

Write hcf(a, b) using Euclid’s method — reuse your divide function from Part 4 to get the remainder.

Got it? Skip to Part 6.

The HCF (Highest Common Factor) of two numbers is the largest number that divides both of them evenly. It’s also called the GCD (Greatest Common Divisor).

Example: the factors of 12 are 1, 2, 3, 4, 6, 12. The factors of 18 are 1, 2, 3, 6, 9, 18. The highest factor they share is 6.

Euclid discovered an elegant recursive rule over 2,000 years ago. Given two numbers a and b (where a is the larger and b the smaller):

  • If b == 0, the HCF is a.
  • Otherwise, hcf(a, b) = hcf(b, remainder of a ÷ b).

Before coding: you already have a way to compute remainders — divide(a, b) from Part 4 returns (quotient, remainder). Extract just the remainder: _, remainder = divide(a, b).

Quick Check: hcf(48, 18) — trace the calls:

  • hcf(48, 18) → remainder of 48/18 = 12 → hcf(18, 12)
  • hcf(18, 12) → remainder of 18/12 = 6 → hcf(12, 6)
  • hcf(12, 6) → remainder of 12/6 = 0 → hcf(6, 0)
  • hcf(6, 0) → b is 0, return 6

Answer: 6.

At each step, the numbers get smaller because the remainder is always less than the divisor. So this recursion always reaches the base case — Euclid proved this ~300 BCE!

Part 6: Tower of Hanoi — Double Recursion

Challenge (skip ahead if you can):

Write hanoi(n, src, dst, spare) that returns a list of (from_peg, to_peg) moves to transfer n discs. One disc at a time, never place a larger disc on a smaller one.

hanoi(1, 'A', 'C', 'B')  # [('A', 'C')]
hanoi(2, 'A', 'C', 'B')  # [('A', 'B'), ('A', 'C'), ('B', 'C')]

Try it yourself! Move all discs from peg A to peg C. Rules: one disc at a time, never place a larger disc on a smaller one.

Start with 1 or 2 discs to discover the pattern, then try 3.

Three pegs: A (source), B (spare), C (destination). A stack of discs on A, smallest on top.

Before coding: for n = 2 discs, work out the moves by hand:

  1. Move the top disc (small) somewhere safe
  2. Move the bottom disc (big) to C
  3. Move the small disc onto the big one at C

Moves: A→B, A→C, B→C. Three moves total.

Now generalize for n discs:

  1. Move top n-1 from source to spare (using dst as temp)
  2. Move disc n from source to destination
  3. Move n-1 from spare to destination (using source as temp)

Steps 1 and 3 are themselves Hanoi problems — that’s why this needs two recursive calls.

def hanoi(n, src, dst, spare):
    if n == 1:
        return [(src, dst)]
    moves = []
    moves += hanoi(n - 1, src, spare, dst)
    moves.append((src, dst))
    moves += hanoi(n - 1, spare, dst, src)
    return moves

print(hanoi(1, 'A', 'C', 'B'))

print(hanoi(2, 'A', 'C', 'B'))
# [('A', 'B'), ('A', 'C'), ('B', 'C')]
print(len(hanoi(10, 'A', 'C', 'B')))
# 1023

Part 7: Fibonacci & Memoization

Challenge (skip ahead if you can):

Write fib(n) using plain recursion. Then discover why it’s painfully slow for large n, and fix it with memoization.

Got it? Skip to the end.

Fibonacci: fib(0) = 0, fib(1) = 1, and for n ≥ 2: fib(n) = fib(n-1) + fib(n-2).

Like Hanoi, this makes two recursive calls per step.

def fib(n):
    # Two base cases, two recursive calls
    # YOUR CODE HERE
    pass

print(fib(0))   # 0
print(fib(1))   # 1
print(fib(10))  # 55
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(0))   # 0
print(fib(1))   # 1
print(fib(10))  # 55

Hint: if n <= 1: return n, else return fib(n-1) + fib(n-2).

Try fib(30). Now try fib(35). Notice how much slower it gets?

To compute fib(5), the function calls fib(3) twice and fib(2) three times. For fib(35), fib(2) gets computed millions of times — the same work repeated over and over.

What if the function remembered answers it already computed?

That’s memoization: store results in a dictionary. Before computing, check if the answer is already there.

cache = {}

def fib_memo(n):
    if n in cache:
        return cache[n]
    if n <= 1:
        result = n
    else:
        result = fib_memo(n - 1) + fib_memo(n - 2)
    cache[n] = result
    return result

print(fib_memo(10))   # 55
print(fib_memo(35))   # 9227465  (instant!)
print(fib_memo(100))  # 354224848179261915075

Hint 1: at the top, check if n in cache: return cache[n].

Hint 2: before returning, store with cache[n] = result.

fib(35) was painfully slow. fib_memo(100) is instant. Same algorithm, just remembering what it already computed. This idea — memoization — is the foundation of dynamic programming.
