def next_numb(arr, m):
    pos = len(arr) - 1
    while pos >= 0:
        arr[pos] += 1
        if arr[pos] < m:
            return True
        arr[pos] = 0
        pos -= 1
    return False

a = [0, 1]
next_numb(a, 2)  # True, a = [1, 0]
next_numb(a, 2)  # True, a = [1, 1]
next_numb(a, 2)  # False (overflow)

Hint 1: start from the rightmost digit. Add 1. If it reaches m, reset to 0 and carry left.

Hint 2: if you walk past index 0 and still carry, return False.

def generate_rec(n, m):
    if n == 0:
        return [""]
    result = []
    for d in range(m):
        for s in generate_rec(n - 1, m):
            result.append(str(d) + s)
    return result

def perms(s):
    if len(s) == 0:
        return [""]
    result = []
    for i in range(len(s)):
        for p in perms(s[:i] + s[i+1:]):
            result.append(s[i] + p)
    return result

print(perms("ab"))   # ["ab", "ba"]
print(len(perms("abc")))  # 6 = 3!
# n choices for first, n-1 for second, ... = n!

Quick Check: How many permutations does a list of 4 distinct elements have?

A. 4    B. 16    C. 24    D. 256

Answer: C. 4! = 4 × 3 × 2 × 1 = 24. Each position has fewer choices because you cannot reuse an element. Compare with generate_rec(4, 4) = $4^4$ = 256, where reuse is allowed.

def are_valid(s):
    stack = []
    match = {')': '(', ']': '[', '}': '{'}
    for ch in s:
        if ch in '([{':
            stack.append(ch)
        else:
            if not stack or stack.pop() != match[ch]:
                return False
    return len(stack) == 0

print(are_valid("([{}])"))  # True
print(are_valid("}{"))      # False
print(are_valid("([)]"))    # False

Hint: use a list as a stack. Push openers. When you see a closer, pop and check if it matches. Empty stack at end = valid.

def find_first_empty_space(board):
    for r in range(len(board)):
        for c in range(len(board[r])):
            if board[r][c] == 0:
                return (r, c)
    return (None, None)

def can_place(digit, row, col, board):
    if digit in board[row]:
        return False
    for r in range(9):
        if board[r][col] == digit:
            return False
    r0, c0 = (row // 3) * 3, (col // 3) * 3
    for r in range(r0, r0 + 3):
        for c in range(c0, c0 + 3):
            if board[r][c] == digit:
                return False
    return True

print(can_place(4, 0, 2, grid))  # True
print(can_place(5, 0, 2, grid))  # False

Hint: block corner is ((row//3)*3, (col//3)*3). Integer division by 3 then multiply by 3 snaps to the nearest multiple of 3.

def solve_sudoku(board):
    row, col = find_first_empty_space(board)
    if row is None:
        return True
    for digit in range(1, 10):
        if can_place(digit, row, col, board):
            board[row][col] = digit    # try
            if solve_sudoku(board):    # recurse
                return True
            board[row][col] = 0        # undo
    return False

solve_sudoku(grid)
print(grid[0])  # [5, 3, 4, 6, 7, 8, 9, 1, 2]

Hint 1: if no empty cell, return True (solved). Try each digit; if can_place allows it, place and recurse.

Hint 2: the “undo” is the key: if recursion returns False, set the cell back to 0 before trying the next digit.

Quick Check: A puzzle has 50 empty cells. Brute force without constraint checking tries how many combinations?

A. 50 × 9 = 450    B. $9^{50}$ — astronomically large    C. 50!    D. 81 × 9 = 729

Answer: B. Each of 50 cells can hold any of 9 digits = $9^{50}$. Backtracking avoids almost all of these by pruning bad branches at the first wrong digit. can_place is what makes it fast.

Why is this fast?

The puzzle has ~51 empty cells. Blind enumeration: $9^{51} \approx 10^{48}$ — the sun would burn out first. Your solver finishes in under a second.

The difference is pruning: can_place kills a bad branch at its first wrong digit. The enormous tree of possibilities almost entirely never gets built.

This is the universal pattern of backtracking:

  1. Enumerate — try every candidate
  2. Check — reject bad states early
  3. Backtrack — undo and try the next

It powers maze solvers, N-Queens, and the * wildcard matcher you built in Pattern Matching.

Enumeration provides completeness (you never miss a candidate). Checking provides speed (you never explore a dead end). Together they solve problems that have no formula.
