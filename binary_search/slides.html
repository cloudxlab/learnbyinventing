Someone thinks of an integer between 1 and 1000. You can ask “Is it less than, equal to, or greater than X?”

def count_halvings(n):
    count = 0
    while n > 1:
        n = n // 2
        count += 1
    return count

print(count_halvings(1000))  # 10
print(count_halvings(16))    # 4
print(count_halvings(1))     # 0

Hint: loop while n > 1, halving each time and counting iterations.

You just computed $\lfloor \log_2(n) \rfloor$. This is why binary search needs only ~10 guesses for 1000 items, and ~20 for a million.

The key requirement: each guess must tell you which half to keep. This works whenever the function is monotone — always increasing or always decreasing.

Part 2: Binary Search on Sorted Arrays

Everything so far searched a continuous range of numbers. The same halving idea works on a sorted array — and this is the version you will meet everywhere, from databases to Python’s bisect module.

The setup changes slightly:

  • lo and hi are indices into the array, not numbers
  • You stop when the indices cross, not at a precision

def contains(arr, x):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == x:
            return True
        elif arr[mid] < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return False

print(contains([1, 3, 5, 7, 9, 11], 7))   # True
print(contains([1, 3, 5, 7, 9, 11], 4))   # False

Hint 1: start with lo = 0, hi = len(arr) - 1. Loop while lo ≤ hi.

Hint 2: mid = (lo + hi) // 2. If arr[mid] == x, found. If arr[mid] < x, move lo = mid + 1. Otherwise hi = mid - 1.

    lo, hi, result = 0, len(arr) - 1, -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == x:
            result = mid

def find_last(arr, x):
    lo, hi, result = 0, len(arr) - 1, -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == x:
            result = mid
            lo = mid + 1
        elif arr[mid] < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return result

Hint 1: when you find a match, don’t stop — save the index and keep searching the half where an earlier (or later) match could hide.

Hint 2: for find_first, on a match set hi = mid - 1 to look left. For find_last, set lo = mid + 1 to look right.

Checking each small ID against every huge ID costs $m \times n$ comparisons. Binary-searching each costs only $m \times \log(n)$ — for 10 small IDs in a million-item list, that’s 200 comparisons instead of 10 million.

def insert_position(arr, x):
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] < x:

def closest(arr, x):
    pos = insert_position(arr, x)
    if pos == 0:
        return arr[0]
    if pos == len(arr):
        return arr[-1]
    if abs(arr[pos] - x) < abs(arr[pos - 1] - x):
        return arr[pos]
    return arr[pos - 1]

print(closest([1, 4, 6, 10], 5))    # 4

def search_rotated(arr, x):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == x:
            return mid
        if arr[lo] <= arr[mid]:       # left half is sorted
            if arr[lo] <= x < arr[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                          # right half is sorted
            if arr[mid] < x <= arr[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return -1

Hint: if arr[lo] ≤ arr[mid], the left half is sorted. Check if x falls in that range; if not, go right.

def days_needed(weights, cap):
    d, load = 1, 0
    for w in weights:
        if load + w > cap:
            d += 1
            load = 0
        load += w
    return d

def min_capacity(weights, days):
    lo, hi = max(weights), sum(weights)
    while lo < hi:
        mid = (lo + hi) // 2
        if days_needed(weights, mid) <= days:
            hi = mid
        else:
            lo = mid + 1
    return lo

Hint: binary search between max(weights) (minimum possible) and sum(weights) (ship everything in 1 day). For each candidate capacity, greedily count how many days it takes.

def find_min_convex(arr):
    lo, hi = 0, len(arr) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] > arr[mid + 1]:
            lo = mid + 1
        else:
            hi = mid
    return arr[lo]

print(find_min_convex([10, 9, 8, 6.5, 4.1, 3.2, 2, 4, 4.5, 6]))  # 2
print(find_min_convex([5, 3, 1, 2, 4]))  # 1

Hint: if arr[mid] > arr[mid+1], you’re on the downhill slope — set lo = mid + 1. Otherwise hi = mid.

“Walk downhill until it stops going down” is exactly how gradient descent trains ML models — you will meet this idea again.

Quick Check: A sorted list has 1,000,000 elements. What is the maximum number of comparisons binary search needs?

A. 1,000,000    B. 1,000    C. About 20    D. About 500,000

Answer: C. Each comparison halves the search space. $\log_2(1{,}000{,}000) \approx 20$, so about 20 comparisons suffice.
