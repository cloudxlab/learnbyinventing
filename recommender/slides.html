Part 1: The Raw Data

Challenge (skip ahead if you can):

Given a CSV of movie ratings (people × movies, many blanks), write recommend(person, k) that returns the top-$k$ movies that person hasn’t seen yet, ranked by how much similar people liked them.

Already got it? Skip to the end.

We have real data: 25 Bollywood movies rated by 18 people on a 0–5 scale. Many cells are blank — nobody has seen every movie.

Quick Check: Why do we normalise per person before comparing tastes?

A. To make the matrix square    B. To strip the rating scale so only the preference pattern remains    C. To remove NaN values    D. To sort the movies alphabetically

Answer: B. A harsh critic’s “3” and a generous critic’s “5” can mean the same thing. Normalising removes the scale and reveals the pattern.

Part 3: Measuring Taste Similarity

Each person is now a column of 25 numbers (one per movie). Two people with similar taste will have similar columns.

How do we measure “similar direction”?

Cosine similarity:

$\text{sim}(\mathbf{a}, \mathbf{b}) = \dfrac{\mathbf{a} \cdot \mathbf{b}}{|\mathbf{a}|\;|\mathbf{b}|}$

Result is between −1 (opposite) and +1 (identical direction). It ignores magnitude — only direction matters.

Hint 1: np.dot(a, b) computes the dot product.

Hint 2: np.linalg.norm(a) computes $|\mathbf{a}|$.

We need to compare every person to every other person. With 15 people, that’s $15 \times 15 = 225$ pairs. Can we do it in one line?

Yes — if we turn each column into a unit vector first. Then a simple matrix multiply gives all cosine similarities at once.

Convert each column to a unit vector (length 1):

M = filled.values   # shape: (25, 15) — movies × people

# Divide each column by its length
# uM = ???
# YOUR CODE HERE

# Verify: each column should have length 1
print(np.sqrt((uM**2).sum(axis=0)))   # all ~1.0
M = filled.values
uM = M / np.sqrt((M**2).sum(axis=0))

print(np.sqrt((uM**2).sum(axis=0)))   # all 1.0

Hint: (M**2).sum(axis=0) sums down each column. Take the square root, then divide.

Now the magic: uM.T @ uM computes all 225 cosine similarities in one shot. Why?

Each entry $(i, j)$ of $\mathbf{U}^T \mathbf{U}$ is $\mathbf{u}_i \cdot \mathbf{u}_j$. Since we already normalised to unit length, the dot product is the cosine similarity.

# Compute the full similarity matrix in one line
# S = ???
# sim = pd.DataFrame(S, index=filled.columns, columns=filled.columns)
# YOUR CODE HERE
S = uM.T @ uM
sim = pd.DataFrame(S, index=filled.columns, columns=filled.columns)
print(sim.round(2))

Quick Check: Why do we convert to unit vectors before the matrix multiply?

A. To make the matrix invertible    B. So that the dot product equals cosine similarity    C. To reduce the number of columns    D. To remove negative values

Answer: B. Cosine similarity is $\frac{\mathbf{a}\cdot\mathbf{b}}{|\mathbf{a}||\mathbf{b}|}$. If $|\mathbf{a}| = |\mathbf{b}| = 1$, it simplifies to just $\mathbf{a}\cdot\mathbf{b}$.

Now the core: score each candidate movie. The score is a weighted sum — people who are more similar to you contribute more to the score of each movie.

$\text{score}(m) = \sum_j \text{filled}[m][j] \times \text{sim}[\text{person}][j]$

In matrix form, that’s just a matrix-vector multiply!

Quick Check: A brand-new user signs up and hasn’t rated any movies. What happens when we try to recommend movies?

A. The system recommends the most popular movies    B. The similarity vector is all zeros — no direction, no meaningful recommendations    C. It crashes with a division error    D. It works fine using the defaults

Answer: B. With no ratings, the user’s vector is all NaN (filled to mean). Their “direction” is meaningless. This is the cold-start problem — the system can’t help until it knows your taste.

Part 5: Item-Item Similarity

So far, we compared people (user-user). We can also compare movies (item-item). Two movies are similar if the same people rate them similarly.

Same trick: normalise each row to unit length, then multiply. This time it’s $\mathbf{U}_r \mathbf{U}_r^T$ (movies × movies).

Quick Check: Netflix has ~300 million users and ~20,000 titles. Which approach produces a smaller similarity matrix?

A. User-user (300M × 300M)    B. Item-item (20K × 20K)    C. Both are the same size    D. Neither is feasible

Answer: B. A 20K × 20K matrix has 400 million entries. A 300M × 300M matrix has 90 quadrillion. At scale, item-item collaborative filtering is far more practical.
