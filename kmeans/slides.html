You're about to find out — by grouping points that "belong together," using nothing but distances and averages.

Part 1: Grouping Points by Distance

Here's a bunch of points scattered on a 2D plane. Your goal: split them into two groups so that points in the same group are close together.

How would you start? You need some notion of a "center" for each group. The simplest idea: just pick two points and call them the centers. Then assign every point to whichever center is closer.

Distance Between Two Points

Before you can group anything, you need to measure how far apart two points are.

If you completed the Expressions & Functions chapter, you already wrote this in Exercise 3.3 — "Distance Between Two Points (2D)." You can reuse that function here.

Write distance(p1, p2) that computes the straight-line (Euclidean) distance between two 2D points.

Recall: the distance between $(x_1, y_1)$ and $(x_2, y_2)$ is $\sqrt{(x_1 - x_2)^2 + (y_1 - y_2)^2}$.

Hint 1Each point is a tuple like (x, y). Use p1[0] and p1[1] to get the x and y coordinates.
Hint 2Compute the difference in x and the difference in y, square each, add them, then take the square root. Use ** 0.5 for the square root.

Assign Points to Nearest Center

You have 10 points and 2 centers. For each point, figure out which center is closer, and put that point in that center's group.

Write assign_to_groups(points, centers) that returns a list of groups — one group per center. Each group is a list of points assigned to that center.

Hint 1Start with one empty list per center: groups = [[] for _ in centers]. Loop through each point and compute its distance to every center.
Hint 2For each point, find which center gives the smallest distance, then append the point to that center's group. You can use min(range(len(centers)), key=lambda i: distance(point, centers[i])).

Find New Centers

You have two groups. The centers you started with were arbitrary — just the first two points. Now that you have groups, can you find better centers?

What single point best represents a group of points?

Write compute_centers(groups) that returns a new list of centers — one per group.

Hint 1The "best representative" of a group of points is their average — the mean of all x-values and the mean of all y-values.
Hint 2For each group, sum all x-coordinates and divide by the number of points. Do the same for y-coordinates. Return the result as a new center: (sum_x / n, sum_y / n).

Quick Check — Grouping

You assigned each point to its nearest center. If you moved one of the centers to a new location, what would happen?

A. Nothing — once a point is assigned, it stays in that group forever

B. Some points might now be closer to the other center, so their group assignment would change

C. All points would switch to the other group

D. The distances would not change because they depend only on the points, not the centers

Answer: B. Distance depends on both the point and the center. Moving a center changes the distances, so some points may end up closer to a different center and switch groups.

K-Means is an unsupervised learning algorithm — it finds structure in data without any labels. No one told the algorithm which points belong together. It figured it out on its own, using nothing but distances and averages.

Quick Check — Why Does It Stop?

In K-Means, you repeat: (1) assign points to nearest center, (2) move centers to the group average. Why does this process eventually stop changing?

A. Python runs out of memory after too many loops

B. The centers bounce back and forth forever — you just stop after a fixed number of steps

C. Each step either keeps the total distance the same or makes it smaller, so the centers settle into a stable position

D. The points physically move closer to the centers each round

Answer: C. Every assign-then-update step reduces (or keeps equal) the total distance from points to their centers. Since it cannot keep getting smaller forever, the centers eventually settle and stop moving.

Part 3: The General Algorithm

Your code works for 2 groups in 2D. But what if you have 3D data? Or want 5 groups? Let's make it general.

N-Dimensional Distance

Your distance function only works for 2D points. Rewrite it to work with points of any number of dimensions.

The Euclidean distance in N dimensions is: $\sqrt{(a_0 - b_0)^2 + (a_1 - b_1)^2 + \ldots + (a_{n-1} - b_{n-1})^2}$

Hint 1Instead of just (a[0]-b[0]) and (a[1]-b[1]), loop through all indices i from 0 to len(a)-1.
Hint 2Use sum((a[i] - b[i])**2 for i in range(len(a))) ** 0.5.

N-Dimensional Centers

Your compute_centers function only averages x and y. Rewrite it to work with points of any number of dimensions.

Hint 1The mean of N-dimensional points means averaging each coordinate separately. If points are 3D, average all the first coordinates, all the second coordinates, and all the third coordinates.
Hint 2For dimension d, compute sum(p[d] for p in group) / len(group). Do this for each d from 0 to the number of dimensions, and collect the results into a tuple.

Part 4: How Many Groups?

K-Means needs you to choose K — the number of groups. But how do you know the right K? What if you pick too many? Too few?

Let's find out by measuring how "good" each grouping is.

Measuring Cluster Quality

How tight are your clusters? One measure: for each point, compute its distance to its center. Sum up all these distances. A lower total means tighter clusters.

Write compute_inertia(centers, groups, distance_fn=distance) that returns this total.

Hint 1For each group and its matching center, loop through every point in that group and add up distance_fn(point, center).
Hint 2Use a nested loop: outer loop over zip(centers, groups), inner loop over points in each group. Keep a running total and return it at the end.

Quick Check — Choosing K

As you increase K (the number of clusters), what happens to the inertia (total distance from points to their centers)?

A. It always goes up — more clusters means more total distance

B. It always goes down — more clusters means each point is closer to a center — but the drop slows after a point

C. It stays the same regardless of K

D. It goes up and down randomly

Answer: B. Adding more centers always makes (or keeps) the total distance smaller, because each point can find a center that is closer. But past the "right" number of clusters, the improvement becomes very small — that is the "elbow" you look for.

You started by measuring distances and making groups. You ended with a general-purpose clustering algorithm that works in any number of dimensions. K-Means is used everywhere — customer segmentation, image compression, document grouping, and as a building block inside larger ML systems.

Going further:

  • K-Means++: Instead of picking the first K points as centers, choose initial centers that are spread far apart. This avoids bad starting positions and almost always converges faster.
  • Mini-batch K-Means: On huge datasets (millions of points), update centers using a random sample of points each iteration instead of all of them.
  • DBSCAN: A clustering algorithm that doesn't need you to pick K — it finds clusters of arbitrary shape by looking at density.
  • Silhouette score: Another way to evaluate clusters — measures how similar each point is to its own cluster vs. the nearest other cluster.
