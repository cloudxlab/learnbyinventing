Part 1: Grouping Points by Distance

Challenge (skip ahead if you can):

Write kmeans(points, k) that automatically groups any set of points into k clusters. It should pick random initial centers, then alternate between assigning points to their nearest center and recomputing centers as group averages — until the centers stop moving.

Already got it? Skip to the end.

Imagine you have a bag of coloured beads scattered on a table. You want to sort them into groups — but you don’t know the colours. All you can see is position.

Here are 10 points on a 2D plane:

points = [[1,2], [2,1], [1.5,1.5],
          [8,8], [9,7], [8.5,8.5],
          [1,8], [2,9], [1.5,7.5], [2,8]]

Can you see the clusters by eye? There are roughly three groups: bottom-left, top-right, and top-left.

Let’s teach a computer to find them — starting with the simplest possible building block: distance.

def compute_centers(groups):
    centers = []
    for g in groups:
        center = [sum(coords) / len(g)
                  for coords in zip(*g)]
        centers.append(center)
    return centers

groups = [[[1,2],[3,4]], [[10,10],[12,12]]]
print(compute_centers(groups))
# [[2.0, 3.0], [11.0, 11.0]]

Hint: zip(*group) gives you each coordinate across all points. Average each coordinate.

You now have three building blocks:

  1. distance — how far apart are two points?
  2. assign_to_groups — put each point with its nearest center
  3. compute_centers — find the best center for each group

What if we just alternate steps 2 and 3? Assign → recompute centers → assign again → recompute … Will the clusters get better?

If we repeat, the centers keep adjusting. Eventually they stop moving — the assignments don’t change any more.

Let’s watch it step by step on our 10-point dataset:

def kmeans_verbose(points, centers, max_iter=20):
    for i in range(max_iter):
        groups = assign_to_groups(points, centers)
        new_centers = compute_centers(groups)
        moved = max(distance(a, b)
                    for a, b in zip(centers, new_centers))
        print(f"Step {i+1}: centers moved {moved:.4f}")

Each iteration, the maximum center movement decreases. After a few steps, it’s essentially zero. The algorithm has converged.

Quick Check: You run K-Means twice on the same points but with different random starting centers. What happens?

A. Always the same result — K-Means finds the unique best answer    B. May get different final clusters — K-Means is sensitive to initialization    C. The second run crashes    D. The second run is always worse

Answer: B. Different starting centers can lead to different local optima. In practice, run K-Means several times and keep the best result.

Quick Check: Does K-Means always converge (stop changing)?

A. Yes — each iteration can only decrease or maintain the total distance; it must eventually stabilize    B. No — it can oscillate forever    C. Only if k = 2    D. Only for 2D data

Answer: A. K-Means provably converges. Each step either reduces the total distance or leaves it unchanged. Since there are finitely many possible assignments, it must terminate.

Part 4: How Many Groups?

We’ve been choosing k ourselves. But what k is best?

We need a way to measure how good a clustering is. Idea: sum up how far each point is from its assigned center. Lower = tighter clusters = better.

def compute_inertia(centers, groups):
    total = 0
    for center, group in zip(centers, groups):
        for p in group:
            total += distance(center, p) ** 2
    return total

c = [[2.0, 2.0], [8.0, 8.0]]
g = [[[1,1],[2,2],[3,3]], [[7,7],[8,8],[9,9]]]
print(compute_inertia(c, g))  # 8.0

Hint: for each point, compute distance(point, center) ** 2 and sum them all up.

Now try different values of k and measure the inertia for each:

for k in range(1, 7):
    best_inertia = float('inf')
    for trial in range(5):
        centers, groups = kmeans(all_points, k)
        inertia = compute_inertia(centers, groups)
        best_inertia = min(best_inertia, inertia)

The improvement is dramatic up to k=3, then nearly flat. The “bend” at k=3 is the right answer — matching our 3 blobs.

This is called the elbow method: plot inertia vs. k and look for the “elbow” — the point where adding more clusters stops helping much.

Quick Check: Why not just use $k = n$ (one cluster per point)?

A. It doesn’t converge    B. Inertia = 0 but no useful grouping — every point is its own cluster    C. It’s too slow    D. Python can’t handle it

Answer: B. Clustering is about discovering structure. With $k = n$, inertia is zero but you’ve learned nothing about the data.
