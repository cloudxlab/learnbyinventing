Imagine you have no weather information at all. A friend calls and asks: “Should I come to play tennis?”

What would you predict, and why?

You’d say Yes — it happened 9 out of 14 times. P(Yes) = 9/14, P(No) = 5/14. These add to 1 because every day is either Yes or No. This baseline guess, before looking at any features, is called the prior probability.

Quick Check: P(Play = Yes) = 9/14. In probability and ML, this is called a “prior.” Why “prior”? Think about it before revealing the options.

Answer: C. “Prior” means before seeing any evidence. It is your baseline belief, computed purely from how often each label appears in the data.

def count_where(data, conditions):
    count = 0
    for row in data:
        if all(row[k] == v for k, v in conditions.items()):
            count += 1
    return count

Part 5: The Zero Problem

Your algorithm has a fatal flaw. Let’s find it.

Look at the data: Outlook = Overcast appears on days 3, 7, 12, 13. What is the Play label for all of those days?

All four are Yes. So P(Overcast | No) = 0/5 = 0.

Now predict for Overcast + Strong Wind + High Humidity. Score(No) includes P(Overcast | No) = 0. Zero times anything is zero. No matter how much other evidence points to No, the single zero kills it.

That’s the zero-frequency problem.

The fix is simple: pretend you’ve seen every combination at least once.

Instead of P(Overcast | No) = 0/5, add 1 to the numerator and k to the denominator (where k = number of possible values for that feature).

For Outlook, k = 3 (Sunny, Overcast, Rainy):

Psmooth(Overcast | No) = (0 + 1) / (5 + 3) = 1/8 = 0.125

This is called Laplace smoothing (or add-one smoothing).

Quick Check: Laplace smoothing adds 1 to every count. What would happen if you added 1000 instead?

A. More accurate — more “data”    B. Nothing — relative ordering stays the same    C. All probabilities approach 1/k (uniform) — the fake counts overwhelm the real data, and the classifier ignores evidence    D. Python crashes with overflow

Answer: C. With a huge smoothing value, fake counts dwarf real counts, making every conditional probability close to 1/k. The classifier forgets the training data. That is why the smoothing parameter (alpha) is typically kept small, like 1.

class NaiveBayes:
    def __init__(self, alpha=1):
        self.alpha = alpha

    def fit(self, X, y):
        self.labels = list(set(y))
        self.total = len(y)
        self.label_counts = {}
        self.feat_counts = {}   # {label: {feat: {val: count}}}
        self.feat_values = {}   # {feat: set of values}
        for row, label in zip(X, y):
            self.label_counts[label] = self.label_counts.get(label, 0) + 1
            if label not in self.feat_counts:
                self.feat_counts[label] = {}
            for feat, val in row.items():
                self.feat_values.setdefault(feat, set()).add(val)
                fc = self.feat_counts[label]
                fc.setdefault(feat, {})
                fc[feat][val] = fc[feat].get(val, 0) + 1
        return self

    def predict(self, X):
        results = []
        for row in X:
            best_label, best_score = None, -1
            for label in self.labels:
                score = self.label_counts[label] / self.total
                for feat, val in row.items():
                    count = self.feat_counts[label].get(feat, {}).get(val, 0)
                    k = len(self.feat_values.get(feat, set()))
                    score *= (count + self.alpha) / (self.label_counts[label] + self.alpha * k)
                if score > best_score:
                    best_score = score
                    best_label = label
            results.append(best_label)
        return results

Hint 1: in fit, loop once through X and y together. Build nested dicts for counts. Return self.

Hint 2: in predict, smoothed P = (count + alpha) / (label_count + alpha * k).

def predict_proba(self, X):
    results = []
    for row in X:
        scores = {}
        for label in self.labels:
            score = self.label_counts[label] / self.total
            for feat, val in row.items():
                count = self.feat_counts[label].get(feat, {}).get(val, 0)
                k = len(self.feat_values.get(feat, set()))
                score *= (count + self.alpha) / (self.label_counts[label] + self.alpha * k)

Continuous features: your classifier works with categories (Sunny, Rainy). But what about actual numbers like temperature = 72.3°F?

P(Temp = 72.3 | Yes) is essentially zero — that exact value probably never appeared in training.

Two approaches:

  1. Bin the numbers into categories (Cold: <60, Mild: 60–80, Hot: >80) and use your existing classifier.
  2. Gaussian NB: assume numerical features follow a bell curve per class. Compute the mean and standard deviation per class, then use the bell curve formula to get the probability.
