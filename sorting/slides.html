def pass_sort(lst):

How much work does bubble sort do? Add a counter to your pass_sort that counts every comparison. Run it on lists of length 10, 100, and 1,000. Fill in the table:

What pattern do you notice? When the list gets 10x longer, how much does the count grow?

The ratio stays near 0.5 — comparisons grow as $n^2 / 2$. This is O(n²): quadratic time.

At $10^8$ operations/second, sorting 1,000,000 items would take $10^{12} / 10^8 \approx$ 2.8 hours. We need better ideas.

Insertion sort is O(n²) worst case, but O(n) when the data is nearly sorted — that’s why Python’s Timsort uses it as a building block.

def merge(a, b):
    result = []
    i = j = 0
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            result.append(a[i])
            i += 1
        else:
            result.append(b[j])
            j += 1
    result.extend(a[i:])
    result.extend(b[j:])
    return result

print(merge([1, 5, 9], [2, 3, 7]))  # [1, 2, 3, 5, 7, 9]

Hint: two index variables. Compare fronts, append the smaller, advance that index. When one runs out, append the rest of the other.

def split_sort(lst):
    if len(lst) <= 1:
        return lst
    mid = len(lst) // 2
    left = split_sort(lst[:mid])
    right = split_sort(lst[mid:])
    return merge(left, right)

Hint 1: base case: list of 0 or 1 elements is already sorted.

Hint 2: split at mid = len(lst) // 2. Recursively sort each half, then merge.

Why is it n·log(n)?

level 0:         [ n elements ]           ~n comparisons
level 1:      [ n/2 ]    [ n/2 ]          ~n comparisons
level 2:    [n/4][n/4]  [n/4][n/4]        ~n comparisons
...
  • Each level does ~n comparison work total
  • How many times can you halve n? That’s $\log_2(n)$ levels

Total: $n \cdot \log_2(n)$. For n = 1,000,000:

  • $n^2 = 1{,}000{,}000{,}000{,}000$
  • $n \cdot \log_2(n) \approx 20{,}000{,}000$

50,000x less work.

partition_01(x)
# All 0-tuples first, then all 1-tuples
print([t[0] for t in x])  # [0, 0, 0, 1, 1, 1, 1]
def partition_01(lst):
    left = 0
    right = len(lst) - 1
    while left < right:
        while left < right and lst[left][0] == 0:
            left += 1
        while left < right and lst[right][0] == 1:
            right -= 1
        if left < right:
            swap(lst, left, right)
            left += 1
            right -= 1

x = [(0,"x"), (1,12), (0,34), (1,90), (1,89), (0,"s"), (1,"7")]
partition_01(x)
print([t[0] for t in x])  # [0, 0, 0, 1, 1, 1, 1]

Hint 1: two pointers — left scans forward past 0s, right scans backward past 1s.

Hint 2: when left points at a 1 and right at a 0, swap them.

def partition(lst, lo, hi):
    pivot = lst[hi]
    store = lo
    for i in range(lo, hi):
        if lst[i] < pivot:
            swap(lst, i, store)
            store += 1
    swap(lst, store, hi)
    return store

def pivot_sort(lst, lo=0, hi=None):
    if hi is None:
        hi = len(lst) - 1
    if lo >= hi:
        return
    p = partition(lst, lo, hi)
    pivot_sort(lst, lo, p - 1)
    pivot_sort(lst, p + 1, hi)

x = [5, 2, 9, 1, 5, 6]
pivot_sort(x)
print(x)  # [1, 2, 5, 5, 6, 9]

Hint 1: base case: if lo >= hi: return.

Hint 2: partition, get p, recurse on (lo, p-1) and (p+1, hi).

Merge sort does its work while combining; quick sort does its work while splitting. Quick sort needs no extra memory.

Quick Check: What input causes quicksort’s worst-case O(n²) when always picking the last element as pivot?

A. Random numbers    B. Already sorted    C. Many duplicates    D. Very short list

Answer: B. When sorted, every partition puts 0 elements on one side and n-1 on the other — n levels of recursion instead of log(n), making it O(n²).

def count_values(ages, max_value):
    counts = [0] * (max_value + 1)
    for age in ages:
        counts[age] += 1
    return counts

print(count_values([3, 1, 3, 0], 3))  # [1, 1, 0, 2]

def tally_sort(ages, max_value):
    counts = count_values(ages, max_value)
    result = []
    for v in range(len(counts)):
        result.extend([v] * counts[v])
    return result

print(tally_sort([3, 1, 3, 0], 3))  # [0, 1, 3, 3]

Hint: loop v from 0 to max_value. Append v to the result counts[v] times.

Complexity: O(n + k) where k is the range. No comparisons at all! But this only works when k is small — you can’t bucket arbitrary floats.
